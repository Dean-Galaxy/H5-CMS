# 08 员工后台 v2 实施与验收说明

状态：用户已确认 UI 并授权派发既有任务实施。原型为外观和操作参考，业务事实、权限及跨模块接口仍以当前确认稿、契约和下述兼容边界为准。

## 共用界面与页面归属

员工后台使用原有应用和业务服务，不另建一套后台，不为照搬参考项目更换框架或引入新依赖。00 先落实共享员工布局、导航、标签、弹窗、表单和金额格式化所需的最小组件；模块只接入这些组件并维护自己的页面。已有观众网站 `components/layouts/site.blade.php` 不因本轮后台样式直接重做。

| 模块 | 现有主要页面 | 本轮目标 |
|---|---|---|
| Identity | `h5-platform/resources/views/identity/staff-accounts.blade.php` 等 | 员工账号、操作审计分栏；新增编辑就近完成 |
| Content | `h5-platform/resources/views/content/library.blade.php`、`preview.blade.php` | 内容与单剧分层导航；移除一页堆叠所有功能的结构 |
| Billing | `h5-platform/resources/views/billing/desk.blade.php` | 订单、价格、客服按标签分开；美元输入和展示 |
| Acquisition | `h5-platform/resources/views/acquisition/desk.blade.php` | 链接、像素、汇总、发送记录分开；美元展示 |

默认进入当前角色可操作的页面。菜单隐藏不代替服务器鉴权；刷新、返回和切换标签保留合理上下文，未保存表单离开时提供保存/放弃/继续编辑选择。窄屏上表单和弹窗重排，重要操作不能被遮挡。

## 02 内容、媒体和发布

### 素材放回业务上下文

- 内容一级：剧目库、发布排期、分类管理、首页 Banner。发布排期保留跨剧查看作用，修改回到对应剧目；不再提供重复的全局素材库编辑入口。
- 单剧：基本资料、分集与字幕、授权与试看、发布设置、操作记录。封面在基本资料上传/替换，视频和 SRT 在分集内上传/替换，Banner 横图在该 Banner 编辑里上传/替换。
- 删除导航不等于删除媒体记录、处理任务、旧绑定或后台处理能力。超过 200 份素材时旧绑定仍可回显，历史 F04 不得回归。
- 批量上传继续按实际集数核对映射，视频和字幕类型分开；真实 UI 不能硬编码样稿中的 8/12/35 集、文件名、语言、日期或处理成功定时器。

### 替换视频与字幕

1. 编辑始终绑定原 episode ID，集数不是定位另一分集的键；不重现历史 F03。
2. 当前文件与候选文件独立显示；视频和 SRT 独立替换，取消一项不清掉另一项或当前文件。
3. 新版尚未就绪、处理失败、取消或提交失败时，当前有效绑定保持。处理完成后仍要明确确认才切换；保存结果未知不能假报替换成功。
4. 已公开分集替换不增加/减少公开集数，不改免费 N、会员事实、授权地区或更新游标。草稿替换后仍是草稿。权限和媒体访问保护沿用现有规则。
5. 必须验证候选素材属于当前剧/集和实际类型、语言，不能仅凭文件名或前端状态信任上传成功。当前绑定发生并发变化时明确冲突，不覆盖他人的更新。
6. 已在播放的旧版本如何保留、何时回收文件，沿用或补齐受控播放/引用策略，不能为替换立即删除仍被有效会话使用的文件，也不承诺无条件永续旧许可。跨模块契约变化交 00。

### 一个完整发布安排

| 选择 | 确认与结果 |
|---|---|
| 全集一次上线＋指定时间 | 必须确认总集数且全集就绪；显示上线时间和全部剩余范围，确认启用计划，不提前公开 |
| 全集一次上线＋现在 | 检查全部剩余集数，明确确认后一次公开；实际完成后才显示全集已公开，计划结束 |
| 分批更新＋指定时间 | 确认首批、更新频率、每批数量和后续安排；尚未到时不增加公开计数 |
| 分批更新＋现在 | 同一次确认覆盖现在的首批和未来剩余排期；剩余未公开集存在时必须填写有效的后续首次更新时间；失败时不能出现「已成功启动后续」的假状态 |
| 计划生效后提前发布下一批 | 保留手动能力，先显示本批范围及对下一批起点/时间的影响，成功后同步游标，定时执行不重复公开 |

示例：35 集、每天 10 集、首批现在上线，页面明确列出现在 1–10，后续第一个指定时点 11–20，再按频率发布 21–30、31–35。首次确认后展示「已公开 10/35」「下一批 11–20」「下次时间」。后续无需重新发布整部剧。

默认值继续按既有确认稿：已完结、北京时间次日 00:00、从第 1 集开始；频率/批量值默认每天/10，仅更新中生效。样稿的固定日期不得复制为生产默认值。

### 兼容边界

- 首批现在上线和后续计划启用必须有一致的服务端结果，考虑重复提交、页面重试及并发；优先复用 Content 服务。需要接口变化时提交 02 契约申请，由 00 冻结，不能自改公共 DTO。
- 定时执行仍检查最新计划版本、下架状态、授权和当前批次就绪；不跳集、不重复发布、不把临时缺集误判完结。手动提前发布后下一待发布集同步，具体排期变化必须在确认中展示。
- 暂停保留已公开内容，恢复确认下次有效时间，不累计突发；下架使旧计划失效，重上架明确恢复或重设。
- **缺素材与服务器错过时点不同。** 既有规则允许补齐素材后手动发布或等待下一正常更新时刻；上传本身不立即补发。样稿「补齐后确认恢复」适用于已进入暂停/待确认的计划，不得据此把所有正常计划强制改成新审批流程。00/02 让文案与实际计划状态一致。
- **D03 仍未决定。** 不把 UI 获批解释为批准服务器故障后的补发窗口或自动追赶；仍明确待处理，不擅自采用 10 分钟规则。D05、外部部署和官方支付等也没有新增授权。

## 01 员工密码与页面

员工、负责人密码创建/重设等实际适用入口统一最低 8 位；保留字母和数字、128 位上限及现行其他保护。页面提示、表单限制、服务端验证、命令行负责人创建和帮助文案保持一致，已有密码散列无需迁移或强制重设。

现行 `CreateOwner`、`StaffManager` 存在显式 12 位限制；`IdentityServiceProvider` 的默认规则以及观众 `CreateViewer`、`ResetViewerPassword` 也有 12 位限制。本轮是员工后台改造：实现时明确员工作用域，不因改一个共享默认而顺带放宽观众策略。若必须调整共享入口，先向 00 说明范围及相应回归。

账号权限、MFA、CSRF、会话撤销、限流和观众/员工隔离继续有效。对 7 位拒绝、符合规则的 8 位接受、缺字母或数字拒绝等做针对验证；不只是把提示从 12 改成 8。

## 03、05 金额与分栏

- 所有面向员工的金额标签、输入、列表、订单详情、汇总和相关导出使用美元/`USD`，最多两位小数。例如展示 `$12.00 USD`，员工输入 `12.00`。
- 账本、DTO、支付 SDK、事件仍使用 USD 最小单位整数；服务端精确转换，`12.00 → 1200`，读取 `1200 → $12.00`。不要用二进制浮点作为记账或价格来源，不改变旧数据单位。
- 拒绝超精度及不合法金额，零值/负值的可用范围沿用既有各字段规则；只读退款金额等不得因输入规范而隐藏实际值。
- 03 保留新老订阅约定价、首惠、报价有效期、付款/退款/权益事实及客服权限。不新增普通退款审批，不开放客服直接退款。
- 05 仅重排已实现后台功能并格式化现有汇总，测试金额仍明确标注。D05、默认装载、网站来源衔接、真实像素和外发不在本轮启动范围。
