# 06 H5 系统验收与部署提示词

请在 H5 独立 Worktree 承担 06 系统验收与部署。先确认总控指定的基础或候选提交，所有证据标记实际代码版本；不能拿一个旧版本的报告证明新合并版本通过。

当前起点为 `h5-billing-v1`、契约 `1.0.2`；先读 `docs/handoffs/00-08-03修复接收与后续开工.md` 和台账，核对标签完整提交。01、02、03 本地组合已接收，本次可以开始检查现有组合、安全、工作区隔离、迁移与备份恢复，并准备可执行部署方案。04/05 完整功能、D03/D05 以及官方/外部条件尚未齐备；只把实际执行的部分记为通过，不等待所有模块才开始工作。

实际运行代码从该标签建独立环境，未准备的素材、价格、账号不得从他人工作区直接搬运。当前可信地区解析和 Stripe 测试驱动有本地环境限制；外部测试站所需的受控 staging 配置、可信地区来源及共同依赖变更先交 00/03 协调，不能靠将公共站标成 local/testing 绕过限制。没有采购授权不购买资源，先给用户最小方案和费用依据。

先读当前工作区 AGENTS.md、docs/H5首版业务规则确认稿.md、docs/多任务开发规划/ 下总计划、契约、验收和台账、docs/contracts/ 以及各模块 docs/handoffs/。缺文件只读 /Volumes/KESU/H5/docs/多任务开发规划/ 定位后报 00，不回主目录改业务。原版始终只读。

你的工作分两段：先准备组合测试和可执行部署方案；等真实条件具备，在获授权测试环境验证，不因缺服务器就停掉所有本地测试。

1. 从干净环境验证可启动及数据库迁移，检查工作区配置不互相污染，运行统一契约和必要组合测试。
2. 重点验注册验证、试看、官方测试订阅、会员播放、续费失败、取消恢复、实际退款同步、下架和自动发布；补充价格变化、重复与乱序事件、对象越权和媒体链接绕过。
3. 检查后台角色和二次验证、会话、CSRF、限流、TLS、公开调试、密钥与日志、上传处理等实际边界。可使用合适扫描工具辅助，但不能拿扫描结果替代业务测试。
4. 检查 05 的本地功能及外部状态分别记录，确认没有测试付款误发正式广告资产。Stripe 官方测试不能后置为“上线再测”。
5. 给出服务器、视频、邮件和域名的最小可执行配置方案，说明用途、费用和需要我取得的账号。预算未定时不采购；公司身份和商户认证由本人处理。
6. 条件具备后部署 HTTPS 测试站，配置私有数据库和媒体访问、真实邮件、任务队列与定时进程、必要日志告警。付款通知、媒体和邮件分别用实际证据验收。
7. 验证服务器重启后任务恢复，发布计划不会重复或意外上架；执行数据库备份和独立环境恢复，核对订单、权益及发布状态。准备不覆盖新支付事实的回退方法。
8. 提供真实手机访问和逐步验收入口；浏览器模拟与真实设备检查分开写结果。不要把 Mac 本机地址说成别人手机也能访问。
9. 将发现的问题写成复现步骤、影响、代码版本和首个失败环节，交 00 分派到原模块。业务修复回原任务进行，你负责接收新的候选提交并做受影响回归。

你可维护跨模块测试、deploy、scripts/ops 和验收部署文档。业务模块和公共根配置的变更先交 00 协调，不趁验收重写支付、权限或内容逻辑。部署到共同测试站由 00 安排串行窗口，避免多任务覆盖同一站点。

交付 docs/handoffs/06.md 和验收报告，列版本、通过与失败场景、外部未就绪项、真实恢复证据和使用说明。产品经理应能据此知道怎么打开、启动、使用、验证和停止，以及正式收费前还缺什么。

只有已核实的部分写通过。目标是核心功能测试版，不启用真实扣款，不代替公司给出跨地区合规结论，不把未执行的部署或备份写成已完成。
