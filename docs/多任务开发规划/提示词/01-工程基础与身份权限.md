你的任务：

1. 查看当前工作树和环境，保留已有变更。如果尚无 Git 仓库，在 H5 根目录初始化，只纳入新工程、共同文档和必要无密钥配置。原版、大型视频、缓存、依赖目录及真实密钥全部排除。新 Laravel 应用放在 h5-platform/。
2. 验证并锁定适合本机且受支持的 PHP、Laravel 13、Filament 5、Fortify、Cashier 和 PostgreSQL 组合，核对已知安全修补。必要运行环境由你处理，解释需要我完成的系统授权；不要让我自己猜安装命令。
3. 交付可重复使用的启动、状态检查和停止方式，包含网站、后台、数据库连接以及开发任务进程。为后续工作区提供独立端口、数据库、缓存、队列和素材目录方案，不默认共享可清空的数据。
4. 实现观众邮箱密码注册登录、邮箱验证、找回重设；免费试看不强迫登录；首次付款需要已验证邮箱的身份条件。实现可受控返回原页面的能力，邮件本地预览和真实送达分开记录。
5. 实现独立后台登录、二次验证、负责人创建停用员工与角色分配。四种固定角色和数据范围按业务文档，服务器验证，不只隐藏菜单；观众注册不能获得后台权限。
6. 建立脱敏审计、请求关联号、会话保护、必要限流和统一错误结构，覆盖令牌失效重放、权限拒绝、禁用账号会话撤销。
7. 将共同接口设计落实为 docs/contracts/openapi.yaml、内部接口和数据类型、枚举及 docs/contracts/examples/，精确列出参数、错误、状态、可空值和样例。02、03、04、05 分别实现业务提供方，你只建共同约定和可测试骨架。
8. 预先安排模块装载、独立路由、后台资源发现和网站布局插槽。暂缺模块显式未就绪；测试桩只在测试或明确本地模拟环境使用，不能在普通运行中假造会员或支付成功。
9. 在根 AGENTS.md 落实多任务范围、文件归属、契约变更和交付规则，保留已有适用内容。确认文档会随基础提交进入其他工作区。

本任务只实现基础与身份，不包办内容、支付、会员账本、观众全站或投流模块。基础验收后公共契约和根配置交由 00 管理，你继续维护 Identity 模块；后续修改按归属申请。
