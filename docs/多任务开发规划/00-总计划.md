## 系统如何组成

技术方向建议沿用新 Laravel 工程、Filament 后台、Fortify 账号基础、Cashier 加 Stripe 托管付款页面、PostgreSQL。网站和后台共享一套业务后端、一个数据库系统，各模块只维护自己负责的数据。视频文件独立存放。

这称为“模块化单体”：用户最后访问一个网站，员工进入一个后台，服务器运行一套业务程序。独立工作区只是开发时的隔离方式，不是要求部署六套网站或维护六套正式数据库。

代码关系：

    01 工程基础与身份权限
      ├─ 02 内容 媒体 发布 播放授权
      ├─ 03 支付 订阅 会员权益
      ├─ 04 观众网站 观看进度
      └─ 05 投流链接 像素 归因

    04 调用 01 的身份、02 的内容及播放、03 的会员及订阅
    02 判断付费播放时读取 03 的会员权益
    05 消费 03 核实后的付款事件，并查询 02 的可投放内容
    06 验证以上组合，并处理部署和恢复演练
    00 维护共同约定、合并版本、分派问题、核定完成状态

框架不会自动保证安全或业务正确。原任务指出的固定口令绕过、对象越权、支付通知验真、续费漏处理和播放地址暴露，都要有专门验收。Filament 官方已披露过多因素认证绕过问题，初始化时需要核对修补版本并执行依赖审计，不复用旧项目锁定的依赖。[官方安全公告](https://github.com/filamentphp/filament/security/advisories/GHSA-52xp-w8hr-xv3c)

## 你怎样创建并使用这些任务

1. 先确认这份规划。当前任务作为 00 总控，后续所有跨模块问题、进度和业务变更在这里汇总。
2. 在当前 H5 项目中新建一个任务，拟名“01 H5 工程基础与身份权限”，首次选择 Local，复制[01 提示词](./提示词/01-工程基础与身份权限.md)。这时还没有 Git 仓库，先由它建立基础。
3. 01 完成后，把它的任务引用或交付单发回本任务。使用[00 接收提示词](./提示词/00-总控与集成.md)，由总控检查并记录真实的共同起点提交。
4. 只有总控明确基础门槛通过，才新建 02、03、04。选择同一个 H5 项目、Worktree，并选择总控给出的已验收 main 分支起点。分别复制对应提示词，不把提示词混发给一个任务。
5. Worktree 可以理解为“同一工程的独立施工副本”。它们不自动同步新进度；总控接收后，其他任务按指示同步新的主版本。依赖安装、测试数据库和本地配置也由任务准备，不能假定自动复制。
6. 当前按00-11范围，05先做独立后台、事件接收和本地发送适配，06检查已接收的01–04组合并准备部署；使用 h5-audience-v1。04已存在且已接收，不重复创建。归因业务先定D05，外部验收等待相应条件。06必须注明实际检验提交，后续修复复测受影响链路。
7. 每个任务做完，把交付单或该任务引用发给 00。你不用手工复制源码、选择合并命令或解决冲突。00 检查改动、合并、组合验证；各任务只负责自己的模块。
8. 发现明确的模块问题，可直接回原任务；不知道归谁就发给 00，由它沿链路定位。问题修复仍要回到主版本复测，不能只在某个独立副本里修好。

Codex 的 Worktree 依赖 Git，并从选定起点创建独立代码副本；新任务可以在输入区选择 Worktree 和起始分支。该说明属于最初规划；当前 Git、基础和 Content 已接收，不再重复执行第 2 步。后续任务使用最新共同起点。[Codex 官方工作区说明](https://developers.openai.com/codex/app/worktrees)

如果界面暂时没有 Worktree 选项，先让 00 核对项目路径和 Git 基础。不要直接让多个任务同时在同一 Local 目录修改文件，也不需要你猜测终端命令。
