# H5 组合验收与问题归属

> 2026-10-21更正：用户发现实际UI偏离08获批设计，F09已开放；00撤回整体UI完成及继续人工验收的放行结论，07暂停受影响验收并保留已有记录与数据。原技术测试事实保留，不等于设计一致。以[00-23](../handoffs/00-23-设计一致性退回与纠偏.md)及后续修复对照为准。


验收针对总控合并后的同一个版本。每个模块自己的测试通过，只能说明该模块在对应条件下通过；最终还要证明网站、后台、支付、视频和发布任务连成同一条业务链。

## 完成状态怎样区分

按“未开始 → 开发中 → 模块自测通过 → 已集成 → 组合验收通过”记录。外部服务单独记录“未配置、待联调、已验证、失败”，不能把模块自测通过直接改成全部完成。

本地模拟、Stripe 官方测试、真实广告平台接收和正式收费是不同证据。首版目标要求 Stripe 官方测试通过；广告平台真实联调按用户决定后置；正式收费不是本次交付承诺。

## 四道验收门槛

| 门槛 | 谁负责 | 必须能证明什么 |
|---|---|---|
| A 共同基础 | 01 提交，00 接收 | 工程可启动、账号和后台权限可验、接口及样例有统一版本、各工作区运行隔离；原版未纳入改动 |
| B 首次完整链路 | 00 集成，02、03、04 配合 | 后台上传并发布 → 网站试看 → 登录并验证邮箱 → Stripe 官方测试付款 → 会员观看 → 自助取消并保留本期 |
| C 全部首版功能与安全 | 06 验证，模块修复 | 自动更新、观看进度、价格规则、异常付款、对象权限、投流本地功能和外部条件按下表逐项有结果 |
| D 交付 | 00 汇总，06 复验，用户操作 | 固定版本有可用入口、使用说明、问题单、部署与恢复证据、外部待办；通过情况能追溯到实际测试 |

门槛 B 的早期本地演示可以先采用模拟付款推进界面，但只记“本地链路通过”；必须追加官方测试支付后才可记 B 完整通过。

## 用户亲自操作的核心场景

01 至 06 在交付时提供实际网址、账号取得方式和每一步按钮名称。下表定义预期行为，不能拿现在尚未存在的网址当入口。

| 编号 | 你怎么验 | 应当看到什么 | 主要责任 |
|---|---|---|---|
| U01 | 用运营账号新增剧，上传封面与连续分集，先保存草稿再预览 | 草稿不出现在公开列表，运营能预览；其他无权限人员不能取得草稿视频 | 02；01 权限 |
| U02 | 发布至少 6 集，访客观看第 5 集再进入第 6 集 | 第 5 集可以看；第 6 集提示登录购买，不能通过直接视频地址绕过 | 02 授权；04 界面 |
| U03 | 注册，先输入错误邮箱再修正，验证后回到原剧集 | 验证前不能首次付款；验证后继续原流程，重复正常登录不反复验证 | 01；04 衔接 |
| U04 | 完成一笔 Stripe 官方测试订阅，查看后台订单和会员页 | 平台付款、本站订单和权益一致；只打开成功页面不会凭空开通；解锁第 6 集 | 03；02 和 04 |
| U05 | 取消自动续费，查看平台及本站，再播放会员集 | 不需客服审批；停止下一期续费，本期至原到期仍可看；取消不自动退款 | 03；04 |
| U06 | 在同一期到期前恢复，再点击购买；改价后对比新老用户 | 恢复用原价、不重复扣款、不重置到期；新订阅用新价，老持续订阅保持约定价 | 03；04 |
| U07 | 调整单剧 N，再修改全局默认分别选择两种同步方式 | 新剧和未覆盖剧按选择变化，重点剧保留；显示受影响数量；当前已开始当集不因改 N 被强制中断 | 02；04 |
| U08 | 用测试时钟配置 35 集更新中，每次 10 集；再试已完结 | 更新中按 10、10、10、5 公开；已完结在上线时刻一次公开齐全全集；日期固定、北京时间明确 | 02 |
| U09 | 在待发布前暂停、恢复、缺一集、补素材、下架再上架 | 暂停不影响已公开；不累计突发、不跳缺集；仅补素材不自动发布；下架后旧任务不能重新上架 | 02 |
| U10 | 游客看到一半，登录购买后返回；另一设备登录再继续；主动重看前一集 | 当前观看衔接，账号进度可跨设备；最新有效重看可以成为继续位置；不会导入别人全部游客历史 | 04 |
| U11 | 换角色操作：客服查订单、运营找价格入口、投流同事找别人链接 | 角色与数据范围符合规则；绕过菜单直接访问接口也会被拒绝 | 各模块；01 提供身份 |
| U12 | 后台改分类和 Banner，网站切换中英文并刷新 | 公开内容同步变化；语言被记住；货币与权益不随语言变化；字幕只显示真实已有版本 | 02、04 |
| U13 | 用投流测试链接访问和完成测试付款，查看各平台本地记录 | 来源可关联，首购和续费口径不同，重复付款事件不重复计数；没有真实资产时明确待联调 | 05；03 事实来源 |
| U14 | 手机上测试注册、邮箱验证、观看、付款返回和取消 | 按钮可用、信息不遮挡、返回不丢剧集；真实手机与浏览器模拟分别记录 | 04、06 |

周期、到期和异常测试由开发任务提供隔离的时间控制或支付平台支持的官方测试办法。用户不必真的等一周，也不能把本地推进时间当作支付平台已经验证了续费。

## 必须由技术测试覆盖的关键问题

| 范围 | 不可省略的测试 | 证据来源 |
|---|---|---|
| 身份与权限 | 密码重设令牌过期和重放；邮箱验证限流；后台二次验证及恢复流程；禁用后会话失效；观众不能充当员工；修改对象 ID 不能访问别人订单或像素 | 01 和对应模块测试；06 复核拒绝结果 |
| 付款与权益 | 假通知拒绝；相同、并发、乱序和延迟通知；金额或币种不符；首购失败不消耗优惠；成功后取消或退款不重获优惠；一账号防重复订阅；取消恢复；续费失败后到期；退款仅撤销对应有效区间；对账修复 | 03 本地异常测试和官方测试记录，06 组合验证 |
| 发布 | 保存草稿不公开；完结必须全集齐；定时与手动竞争；执行同时改计划或下架；崩溃恢复不重复发布；缺集不跳过；过期排期使用已经确定的处理规则 | 02 执行记录、数据库断言、受控时间测试 |
| 媒体 | 私有文件无法绕过许可；清单分片及 Range 访问控制；过期或篡改许可拒绝；上传类型与大小、路径穿越及恶意文件名；字幕和文案不注入脚本 | 02 测试，06 从实际部署入口复核 |
| 页面与进度 | 假付款成功页面不开会员；状态未知显示处理中；延迟进度不覆盖新会话；主动重看不会被“最大集数”逻辑吞掉；登录付款返回受控，不能开放重定向 | 04 单模块和浏览器场景 |
| 投流 | 链接和像素对象越权；禁止任意脚本；来源冻结；付款事件去重；失败重试不影响订单；测试与真实发送隔离；首购和续费分类；隐私选择参与发送判断 | 05 本地记录，真实平台证据另填 |
| 运行安全 | 关闭对外调试；密钥及隐私不进源码和日志；数据库不暴露公众访问；TLS 校验；HTTPS、会话和入口限流；任务进程启动停止；备份还原验证；部署回退不覆盖新付款事实 | 06 配置证据、日志、还原与回退演练 |

不以固定测试数量作为完成标准；围绕风险和实际改动选择必要用例。一次通过后，不为凑数量重复运行与变更无关的检查。

## 出问题找哪个任务

| 你看到的问题 | 首先找谁 | 它需要沿着什么证据定位 |
|---|---|---|
| 无法登录、验证或重设密码；后台账号权限异常 | 01 | 请求 → 邮件或令牌 → 身份与会话 → 具体权限 |
| 视频传不上去、集数或定时发布时间不对 | 02 | 上传记录 → 媒体就绪 → 发布计划 → 实际公开记录 |
| 扣款、会员期限、优惠、取消或恢复不对 | 03 | Stripe 测试记录 → 本站付款 → 权益区间 → 展示接口 |
| 页面按钮、布局、语言、播放器交互或观看进度有问题 | 04 | 页面操作 → 请求响应 → 播放会话或进度保存 |
| 投流链接、像素配置、来源或统计不对 | 05 | 链接访问 → 来源快照 → 已核实付款事件 → 去重和发送 |
| 测试站打不开、服务重启后不更新、邮件部署或备份问题 | 06 | 部署版本 → 进程和配置 → 服务连通性 → 日志及还原结果 |
| 付钱后不能看、多个模块说法不同、无法判断责任 | 00 | 先查 03 是否有权益，再查 02 是否发许可，最后查 04 播放；按首次不一致的环节分派 |

不要让 04 通过“强行显示已付费”修复 03 的记账问题；也不要让 03 通过“再送几天会员”掩盖 02 的授权问题。先定位真实断点，再由负责该事实的模块修复。

## 最终交付包

00 交付一个主版本，附以下内容：

1. 实际可用的观众网站和后台入口；本机与外部测试站分别说明，手机怎样访问写清楚。
2. 负责人及各角色账号的建立或领取办法；不要在仓库或公开页面明文放密码。
3. 打开、启动、查看状态、停止、上传剧集、配置发布、测试支付和取消续费的大白话说明。
4. 固定提交版本、契约版本、已验收场景、失败项和外部待办；Meta、TikTok、Stripe 分别记录状态。
5. 任务和模块对应表、问题排查入口、数据库备份与实际恢复结果。
6. 正式收费前还缺的公司、支付、内容、地区规则、隐私、税费及服务配置核对，不能把测试版写成可直接正式收费。

扫描工具只提供辅助发现，不能证明支付和授权天然安全。最终是否完成以实际范围和证据判断。
