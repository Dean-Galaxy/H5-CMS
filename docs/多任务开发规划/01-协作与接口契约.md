## 统一基础规则

- 站内标识对外统一为不透明字符串；具体生成方式由 01 选定并写入契约。Stripe 等外部编号分开存，不当作可由前端决定的站内归属。
- 金额使用最小货币单位的整数，附币种 USD。正常周价与首周价是独立字段，价格和优惠资格由 03 计算；页面不提交可信价格。
- 时间接口统一带时区的 ISO 8601，存储使用 UTC；发布业务按 Asia/Shanghai 计算并显示。权益区间采用包含开始、不包含结束的语义。
- 区分订单状态、支付状态、订阅状态和当前观看权益。订阅“取消续费”不等于立刻无权观看，Stripe 的单个状态字段也不能取代本站已付款权益账。
- 浏览器使用受保护的会话；改变状态的请求验证会话、CSRF 和资源归属。后台会话与观众身份分开，观众登录不能进入后台；后台敏感操作验证角色和对象范围。
- 分集序号从 1 起；“已发布集数”“总集数”“免费集数”分开。前台不把后台默认“已完结”直接当成公开全集的事实。
- 配置更新采用版本或同等的并发保护，过期更新要明确冲突，不能悄悄覆盖同事的新设置。
- 请求包含或返回可追踪的 request_id；日志不记录密码、完整支付凭据、私密播放链接和不必要的个人信息。
- 状态码与业务错误码统一。浏览器页面可由同一进程内的服务渲染，不要求各模块互相发网络请求或另搭微服务。

## 必须统一的服务接口

下表的名字是本轮建议的契约名称，01 在 v1 中落实精确参数和类型，02 至 05 分别实现自己的提供方。接口变化由 00 发布，不由某个消费者猜字段。

| 接口 | 提供方 | 使用方 | 必须返回或接受什么 |
|---|---|---|---|
| IdentityContext | 01 | 全部模块 | 服务端可信的当前观众或后台人员、邮箱验证状态、角色及数据权限；不接受前端任填 user_id 冒充本人 |
| AuditRecorder | 01 | 02、03、05、06 | 操作人、动作、对象、结果、脱敏变更、关联号与时间 |
| CatalogReader | 02 | 04、05 | 已公开剧目和分集、封面、简介、实际发布数、观看所需状态；不包含永久私有视频地址 |
| MembershipReader | 03 | 02、04、客服 | 当前有效已付权益、有效起止、是否续费、是否存在进行中的订阅或待核实付款、可执行的订阅操作 |
| BillingService | 03 | 04、客服 | 服务端报价、创建或恢复唯一支付过程、查询结果、取消和恢复；后台代取消使用已核实请求和审计，不允许客服恢复 |
| PlaybackAuthorizer | 02 | 04 | 当前剧集公开与媒体状态、地区授权、免费规则及会员核验后的短期播放许可，或明确拒绝原因 |
| ProgressService | 04 | 观众页面 | 当前账号的剧、集、播放位置、会话内序号和服务端保存时间；可处理延迟写入，不把用户主动重看旧集丢掉 |
| AttributionService | 05 | 04、03 | 验证来源标记、获取可冻结的来源快照；05 未启用时明确为空，不能阻塞付款 |
| PaymentSettled.v1 | 03 | 05 | 已核实付款事实、稳定事件 ID、站内付款 ID、金额币种、首购或再次订阅或续费、优惠标记、实际发生时间、测试标记及来源快照 |

MembershipReader 返回的“当前有权观看”和“是否仍有未结束订阅”是两件事。续费失败可能没有当前权益，但仍有待处理原订阅；04 不得因此展示可以直接创建第二份订阅的路径。

以下 URL 为建议 v1 设计，01 落地时核对 Fortify 和 Filament 的路由机制，再冻结准确 OpenAPI。后台资源采用模块内 Filament 页面，权限要求与 API 一致。路由是否调整由共同契约说明，不能各自实现不同版本。

| 所属 | 建议接口 | 权限和结果 |
|---|---|---|
| 01 | /api/v1/auth 下注册、登录、退出、当前身份、验证邮件及密码重设 | 验证与重设限流，令牌过期与重复使用规则；敏感响应不泄露账号是否存在 |
| 02 | GET /api/v1/catalog、GET /api/v1/dramas/{id} | 访客可读允许公开的内容；下架旧地址返回不可用 |
| 02 | POST /api/v1/episodes/{id}/playback-grants | 访客也可申请免费内容许可；会员集服务端检查；响应不暴露持久媒体位置 |
| 03 | GET /api/v1/billing/offer、GET /api/v1/me/membership | 返回当前可信报价和本人权益；访客报价不承诺最终优惠资格 |
| 03 | POST /api/v1/billing/checkout、GET /api/v1/billing/orders/{id} | 登录且首次付款前已验证邮箱；创建带幂等标记；查询只限本人或有权限客服 |
| 03 | POST /api/v1/billing/subscription/cancel、POST /api/v1/billing/subscription/resume | 取消无需人工审批；恢复须主动确认下次时间和原约定价；状态未知不假报成功 |
| 03 | POST /webhooks/stripe | 唯一官方支付通知入口；验签、归属、金额币种、重复及乱序处理；不使用普通用户会话作为信任依据 |
| 04 | GET 和 PUT /api/v1/me/progress/{drama_id} | 只读写本人进度；保存进度不授予播放资格 |
| 05 | GET /r/{code} | 受控推广链接；校验目标剧和链接启停，不允许任意外站重定向 |

建议数据契约包含：

- Offer：offer_id、price_version、currency、regular_amount_minor、first_week_amount_minor、eligible_for_first_offer、expires_at、next_renewal_amount_minor。零价是否允许属于金额配置规则，不自行当作免费试用。
- Membership：access_active、access_from、access_until、renewal_enabled、subscription_state、payment_resolution_required、next_renewal_at、next_renewal_amount_minor、allowed_actions。
- PlaybackGrant：grant_id、episode_id、allowed、reason、short_lived_url、expires_at、play_session_id。拒绝时不返回媒体地址。
- Progress：drama_id、episode_id、position_seconds、play_session_id、sequence、saved_at。播放位置需在媒体有效时长内；过期会话写入不覆盖更新会话。
- PaymentSettled：event_id、schema_version、payment_id、order_id、subscription_id、transaction_kind、discount_applied、amount_minor、currency、occurred_at、is_test、attribution_snapshot。
- Error：code、message、request_id、可选字段错误和是否可重试。统一包括 EMAIL_UNVERIFIED、MEMBERSHIP_REQUIRED、UNPUBLISHED、REGION_BLOCKED、MEDIA_NOT_READY、BILLING_PENDING、SUBSCRIPTION_EXISTS、STALE_VERSION、NOT_AUTHORIZED、DEPENDENCY_NOT_READY。

这些是最初设计的最小字段。01 和 00 已将状态值、可空规则、HTTP 状态码、正反样例和消费测试落到冻结契约；当前准确响应以文首所列契约文件为准。具体业务提供方未接入时仍返回未就绪。

## 几条不能分叉的业务链路

付款：04 展示 03 给出的报价，用户登录验证后由 03 创建 Stripe 支付过程。返回“付款成功页面”仅触发查询；03 核实官方付款、订单归属、金额及币种后才记付款和权益。02 通过 MembershipReader 核验，最后发放播放许可。05 只接收 03 已核实的事件，不从成功页生成真实付款转化。

订阅：同一账号只能有一份进行中的订阅。取消调用 03，平台执行结果核实后显示停止续费；请求超时显示处理中并后台核对，不要求人工批准，也不谎报已取消。恢复原订阅保留原续费价和到期日；不能以创建新订阅代替恢复。

权益：按实际付款对应周期记录，不能收到一次通知就在“现在”加七天。重复、并发、延迟和乱序事件不重复发权益；退款仅影响对应款项产生的权益。Cashier 可以承接渠道基础，但不能让框架默认状态覆盖已确认的本项目规则。[Stripe 订阅通知](https://docs.stripe.com/billing/subscriptions/webhooks)

广告事件：付款记录和待发送事件在同一业务事务中可靠落地；提交后异步交给 05。05 按稳定 ID 去重并重试，外部发送失败不回滚付款或会员。测试付款永远不得当作真实收入发到正式广告资产。

发布：02 独占发布事实，任务执行时重读计划版本、内容下架状态、授权和素材就绪情况；按“计划版本加计划发生时间”防重。手动发布同步游标，暂停、修改和下架使旧任务失效。每次实际公开后才更新公开计数。

播放：02 同时判断发布状态、地区许可、媒体可用、免费集数和会员；媒体对象保持私有。领取许可与实际取视频、清单、分片及 Range 请求均须有访问控制，不能只保护一个接口而暴露原始文件。续签不能无限沿用失效会员或已下架内容。

免费规则：仅修改 N 时，不强行中断已经开始的当集正常播放。02 用受限的当前播放会话保留本次免费判断，刷新或切集重新判断；会员退款、下架、授权到期是独立变化，不因此豁免。具体播放许可时长和撤销边界要有记录及验收，不承诺绝对防录屏或防盗版。

## 还需集中确定的实施选择

以下仍为方案建议，不是用户之前已经确认的规则。由 00 统一记录用户的新决定或提出一次成组建议，模块不能各问各的、各选各的；无依赖部分继续推进。

| 问题 | 建议处理与决定时点 | 影响 |
|---|---|---|
| 正式价格与首周优惠金额 | 后台配置；测试采用明显标注的样例价，不把 12 美元方向当最终价格；正式收费前由负责人保存实际值 | 03、04；不阻塞模拟开发 |
| 调价时未付款报价 | 建议有效期内保留已展示的价格快照，过期后重新确认新价；具体时长和 Stripe 会话期限由 03 核对官方限制后交 00 定稿 | 首次官方支付验收前固定 |
| 故障错过发布时刻 | 建议标记待处理并提示运营确认下一次时间，不累计多批突发；与短时同批幂等重试区别开；不默认沿用此前未确认的 10 分钟窗口 | 02 的异常验收前固定 |
| 法定和异常退款操作 | 首版建议负责人通过支付平台执行，本站核实同步实际结果；部分退款先记录与核对，不自动按全额退款撤销所有权益；正式政策另行核查 | 03 退款同步验收及正式开放 |
| 广告来源和像素变更归属 | 建议下单时冻结可验证来源及像素配置版本，历史订单不随之后换像素改写；归因窗口和覆盖策略集中确定 | 05 本地业务验收前固定，真实隐私与平台设置在外部验收落实 |
| 视频 邮件 服务器与预算 | 06 给出有费用和用途的最小选项，用户决定账号和采购；01、02 适配已选服务 | 外部部署及送达验收，不能把本地通过写成外部通过 |

这些待定项必须在对应验收前收敛；若届时仍未决定，只能交付明确的部分成果，不能替用户做未授权的商业选择或自行宣布全部完成。

## 变更和集成流程

1. 模块发现缺字段、共享配置或另一个模块问题，先在自己的交接单写出当前契约、所需变化、消费者和最小影响；创建 docs/contract-requests/ 下的本模块变更记录。
2. 00 判断是否是技术调整或业务决策。技术兼容调整由总控处理，不逐项向用户索取重复许可；真正改变收费、体验或采购范围的集中交用户决定。
3. 00 更新共同契约及样例，交付版本和提交；受影响任务同步后改自己的实现。不能只在聊天里口头约定。
4. 模块交付只包含本任务变更与必要证据，写明是否使用模拟，提交后由 00 检查归属、契约测试、迁移及相关业务测试。
5. 00 合并到主版本，运行最小组合链路。若失败，按首个不一致的环节退回模块修复；不把冲突简单选择“全部保留本方”。
6. 06 对固定候选提交复核。交付单、源码和测试报告必须指向同一个提交，不能拿旧报告为新组合背书。
