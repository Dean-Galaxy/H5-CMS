## 3. 建议采用的最小提交顺序（供00冻结）

2. 创建请求只验证/提交必要身份与协议字段；现有Fortify身份、CSRF、密码、验证邮件及受控返回规则继续。必要条款缺失按正常注册校验拒绝；两项可选意向为false/未选不能成为身份错误。字段白名单不得把05目的草稿mass-assign入Viewer。
3. 明确知道账号已创建并有当前web身份后，才通过00冻结的公共用途端口向05提交本次确实改动的目的。需要时先回读05状态/版本；不保存密码/邮箱/验证码作为重试材料。两目的分别保存、分别回执，不用跨Identity/Acquisition长事务绑住建号；05内部用保存点确保其故障不污染必要业务。
4. 页面先确认账号结果，再显示各目的真实保存结果；保存全部已确认或无新目的请求后可继续原允许页面。部分失败/未知时沿08提示“账号已创建；可选偏好未确认保存，本浏览器相关采集已暂停”，提供“继续使用”和“重试未确认项”；不能再次提交注册，也不无限阻塞必要服务。普通非JS路径同样不能把可选保存当建号前置，应有继续使用/之后管理的退化路径。

两个重要顺序边界：

- 账号创建失败时，不运行“关联新账号”的后置保存。若用户此前通过独立隐私动作已成功关闭C/广告，拒绝仍生效，不能随注册失败回滚。账号已创建但邮件发送/HTTP回程失败时，先用既有必要身份结果/登录确认账号，不重复创建或补发可选grant。
- 必要条款版本失效可阻止接受旧条款的新建号；可选notice/策略版本失效只使相应用途未确认/受限，不能因此撤销已成功账号。两种版本冲突不能混成统一“注册失败”。
