## 5. 候选政策、状态与标识生命周期

### 5.1 分开的状态，不能把政策写成主动同意

建议新增概念而非修改原consent布尔值：

| 概念 | 建议字段/状态 | 可信来源 |
|---|---|---|
| 资格判定 | `eligibility=eligible\|ineligible\|unknown`、`reason`短枚举、`jurisdiction_policy_id/version`、`assessed_at/valid_until` | 服务端核准政策+受信部署地区证据+实际条件；前端不得指定国家/州/年龄结果 |
| 第一方C | `basis_kind=policy_permitted\|explicit_opt_in\|none`，`site_choice=unset\|allow\|deny`，`notice_version`，`site_effective=on\|off` | policy_permitted不是granted；浏览/关闭告知不改变用户choice。主动解除拒绝记录action=allow，仍复验资格，不伪造旧consent |
| 增强 | `account_link_choice=unknown\|granted\|denied`、`granted_at/withdrawn_at/version` | 独立用户动作、必要会话/CSRF及01可信viewer；不随注册/条款接受自动打开 |
| 转化 | `conversion_link=off\|account_opt_in\|separately_reviewed`、`conversion_basis_version/effective_at` | 建议仅account_opt_in进入首版候选，另一路须再次冻结；账户增强拒绝不旁路建映射 |
| 广告 | 沿用原广告选择/撤回、`advertising_effective`及退出信号判定 | D05与平台核定独立；C不生成source；GPC冲突时广告off优先，不自动清除或授予C选择 |
| 执行证据 | 选择事件、政策版本、告知版本、实际生效时刻、环境、撤回/抑制状态 | 安全审计白名单；不存完整IP/UA/URL、邮箱、生日或广告ID来“证明同意” |

优先级：模块/部署未准入或故障→off；未知/不合格、过期政策/地区冲突→C off；旧明确拒绝/撤回、当前deny/暂停→对应off；告知未就绪→off；其余才按核准basis启C。`account_link`或`advertising`允许不扩大C资格。已知未成年人首版候选不启C/账户增强/广告（保守产品范围，不宣称全美法律都相同）；未知年龄须使用被明确批准的受众条件，而不是自动写adult=true。对不满足C者保留必要服务，不能绕现有地区/版权/会员许可；既有独立合法opt-in仅按原冻结目的处理，不偷换成C默认采集。

### 6.1 可信地区与告知前置

当前`ServerRegionResolver`真实返回ZZ；不能改其全局判断、`ResolvedRegion`或production Guard来方便C。向00申请独立的测量政策解析结果，复用06认可的信任链：只有部署反向代理身份已验证才取其地区结果，客户端`X-Country`/`X-State`、任意转发头均不能启C；本机US测试仅testing/local合成用例。位置与居住/适用差异不能靠GeoIP精度解决，需核准策略说明；地区超时/缺失/冲突/境外→未知/回退，禁止先开再补证据。

告知需要在可选处理前实际可见且入口可用；建议context只作能力/政策状态查询、不建C主体，前端就绪后调用start。告知呈现确认只是技术证据，不是读懂证明或用户同意。失败不初始化ID/队列；当前已可见页面只在C实际开始后记一次当时page_view，不回报进入前停留/播放历史。

### 6.2 普通UTM作为独立本站渠道候选，不能混同广告D05

**可以申请，但普通UTM不天然非个人数据或无需授权。** 建议首版该功能默认关，另列`local_channel`处理范围：只接`utm_source/utm_medium/utm_campaign`中与**服务端预登记粗分类**完全匹配的短代码，原始值不存；映射为`local_channel_code`及campaign目录版本，不允许自由文本、员工联系方式、受众/用户独有码、内容敏感标签。`utm_term/utm_content`、fbclid/ttclid/fbc/fbp/ttp和其他query不进入C。未获有效C前不读取/持久化这些字段作分析；不把当前浏览器整条URL存队列等待以后许可。服务器/网关可能先看到URL，故query日志须先核与脱敏，不能用日志回填。

范围仅本站链路质量比较：C会话开始时根据当时可用且获准的粗代码定入口，**本会话固定，不跨会话存渠道，不延长C标识或D05**。新会话无获准代码=unknown，不从上一会话、广告source或referrer补推；普通导航不悄改已有会话入口。外部广告创意/活动携带的UTM仍可能与平台归因目的重叠，须按实际用途核定；不能以“本站UTM”为名跳过广告拒绝或传平台。若用户广义拒绝营销来源关联则该范围off。

该候选不是原`channel/link_id/source_id`：新字段只能筛自己的C样本，不连接Acquisition广告资产/历史订单；没有已核准员工资产范围映射时仅Owner看本站渠道汇总，投流员工不因此看到全站。单剧/单集维度只在获准C样本内查询。验证需含合法预登记代码、未知/大小写/重复query/编码异常/超长/用户独有码拒绝、不写日志、跨会话不继承、无D05副作用。是否核准此用途、词典、告知与期限由00冻结，不先改变`/r`转发白名单。

## 7. 事件、顺序、观测窗和可信财务

沿用既有事件含义，C使用独立schema/存储分区或等价强隔离，不把原同意后样本改成默认C样本。

| 来源 | 候选事件 | 约束 |
|---|---|---|
| 04浏览器 | page_view,drama_view,play_requested,play_started,watch_progress,episode_completed | 可见后page_view；play_started需时间前进；watch_progress累计实际观看增量、seek不算，节流建议10秒且离页尽力一次；完成需已开始且符合服务端复核时长，不信任随意duration |
| 04浏览器 | player_startup,player_stall,player_error,paywall_view,subscribe_click,registration_view,registration_submit,verification_view,checkout_click,payment_return_view | 展示/提交/返回不是成功；页面/播放实例幂等，预加载和机器人识别只尽力，不承诺绝对真实人类 |
| 01受信服务器 | registration_succeeded/failed,login_succeeded/failed,email_verified,logout | 基础C仅原请求有效上下文最小结果；异步email_verified若只能靠账户回查且未增强，不补关联；退出事件后旋转，换号不得继承 |
| 04受信服务器 | checkout_created/failed,payment_pending/cancelled/failed | 即时结果可在当前C会话剥离order后记枚举；异步结果无获准映射则不关联C，pending不能当失败 |
| 03原事实→05 | payment_confirmed,refund_confirmed,subscription_cancelled/resumed | 仅原可靠事实/Reader；映射需事前核准并在checkout捕获，不能靠当前无关会话/后来的grant/账户扫描回填。续费单列，不当新客；超C窗口仍是03事实，不能硬塞原游客漏斗 |

错误枚举沿用现`EventProperties::ERROR_CODES`，候选收敛为分类映射：validation/credentials/rate_limited/authentication/authorization/network/media/region/membership/timeout/unavailable/internal/unknown/payment_pending/payment_cancelled/payment_failed；旧枚举只由服务端固定表映射，不接自由错误消息/URL。C停用等诊断用无逐人短枚举，例如`POLICY_UNRESOLVED,NOTICE_NOT_READY,SITE_OPTOUT,LEGACY_DENIED,REGION_UNTRUSTED,ACCOUNT_LINK_REQUIRED,CONVERSION_MAPPING_ABSENT,CONTEXT_EXPIRED`，只汇总计数。

分析分母为同一入口时段、同一有效C主体/会话/政策样本：分别报30分钟会话内路径和以入口为起点7天的同浏览器主体路径；subject绝对7天期限内才有关联。按服务器时间及单调sequence排序；可信03时间和同单因果下界沿原口径，不修改原paid_at。步骤允许实际合法路径差异，不强制注册必须位于播放前；已登录样本与新游客注册样本分开。一个主体多会话≠多个真实人，不用“UV”暗示全体独立自然人。

显示进入人数（可观测主体数）、每步去重数、上一步同群比例、仍在观察中、等待可信到达宽限、被撤回/资格结束造成不可继续观测的数量/原因；**观察结束无后续只能叫“未观察到下一步”**，不能精确断言退出/原因。player错误是已观察类别，不把没有付款都归技术故障。只比较实际存在且相容的地区/渠道代码/内容/时段/环境/政策版本维度；样本变化不是转化提升，未知维度显式unknown，不用识别会话/PV做人数覆盖率。现10000入口上限须继续明确processed/total和比例不可完整计算，不靠截原始事件数漏掉付款。

登出/换号仅结束浏览器当前测量上下文，不等于撤回原先合法的最小转化映射：原checkout已获准的迟到付款仍只按原事实时资格、原映射及当前真实撤回/法律政策判断，不能借新账号会话。明确C拒绝/撤回/删除才停止相应后续C关联；广告另按原D05，03原账务始终保留。7天标识到期只终止继续浏览的旧标识，8天接收宽限不能重建它或采集窗外事实；接收时政策已禁止该用途则Skipped，而非仅因历史存在而继续处理。

付款事实接收和C测量是两个结果：原PaymentReceiver/03 outbox不能因C off/退出/无映射而失败，亦不能标广告发送成功。临时C存储故障在独立可靠测量副任务标Retry，不回滚订单/权益、不重复业务收入；无资格/撤回/缺事前映射为终止Skipped并安全诊断。任何重试只用原时刻、原用途上下文，同一付款稳定key不重复转化；不能因后来C开启将旧03已Skipped事件变Accepted。若为复用旧可靠outbox需新的测量分发状态/公共接口，交00/03冻结后才实施，不让一份Ack同时代表多个用途。

## 8. 候选公共接口与API样例（非已发布API）

建议00新增独立`FirstPartyMeasurementContext`与`FirstPartyOutcomeRecorder`等效接口，不改原`BehaviorEventRecorder::record/recordFact/clearBrowserContext`签名，不用新字段绕原v1校验。候选方法：

```text
Context.capture(): ?MeasurementContextSnapshot
Outcome.record(name, minimizedProperties, stableKey, capturedContext): Accepted|Skipped|Retry
```

capture由服务器根据生效C会话捕获，不接浏览器任意subject/order/source；DTO含内部上下文引用、处理范围、policy/notice版本、生效/过期/环境及撤回校验引用，客户端不可伪造。01/04的可信结果在原请求捕获；03异步事实仅用事前核准映射。未配置实现不冒成功，可靠测量任务返回Retry，明确永久不适用才Skipped；普通采集失败不阻塞业务。

候选路径（待00接收装载）：

| 路径 | 建议语义与兼容 |

| GET `/api/v2/measurement/context` | 必要会话/no-store；只返回公共有效状态、资格短原因/版本、当前选择、是否须先展示告知，不创建测量主体/不返回内部ID。eligibility缺失off |

| PATCH `/api/v2/measurement/preferences` | 单个或多个明确作用域动作、`notice_version,expected_revision`；客户端先暂停对应可选采集，再原子保存/回读。服务端revision冲突409返回真实状态、不清草稿。禁止viewer/region/basis字段 |

这里GPC仅使相应广告用途off；没有将site_choice写allow或legacy.analytics写granted。未知资格返回`eligibility=unknown,basis_kind=none,site_effective=off,reason=POLICY_UNRESOLVED`，并不把广告/增强用户意向当启用事实。
