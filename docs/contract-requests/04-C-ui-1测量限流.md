# 04 C首轮真实浏览器发现：测量接口共享限流计数

2026-10-30；基线841bed779a8a7157c92f0e8fc6940de4ff83e142，c-core-1 / c-ui-1。交00协调05修复；04不改公共路由。

在04新独立标记测试库、真实Laravel HTTP和Chrome中，先后浏览/播放/关闭等独立用例后，正常的偏好重试返回429 `RATE_LIMITED`，不是期望的成功或409。私密证据 `.runtime/c-ui-1/browser-failure.json`（第2轮）；页面已按未知保存失败保持本页暂停、保留关闭意图，没有冒报服务器关闭。

原因：`routes/modules/acquisition.php` 的context/events `throttle:120,1`、start `60,1`、preferences `30,1` 都使用默认未命名签名。当前框架 `ThrottleRequests::resolveRequestSignature()` 取domain/IP，未按endpoint分开；数值限额不同不产生独立key。context/events的正常请求因此也累计到偏好30限额；不只自动化重跑会累积，正常播放持续上报也可能挡住关闭。当前无账号的同IP多个浏览器亦共享此计数。

建议05为C的只读、启动、事件与必要偏好操作配置分别命名/前缀的限流，并验证正常可选采集流量不耗尽关闭额度，保留CSRF、可信会话与合理滥用防护；不信任浏览器传身份。修复由00接收，04复验实际HTTP。无需增加公共DTO字段或改冻结响应。

04会在各独立浏览器用例前清理**自己这个标记合成库的缓存**，防止先前独立用例互相消耗额度；另保留真实共享限流压力用例，明确这是已发现的公共问题，不能据此声称组合验收通过。本地暂停只是故障保护，不能代替服务器关闭。
