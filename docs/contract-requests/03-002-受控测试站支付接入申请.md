## 3. 建议冻结的环境矩阵

“公共安全条件”指下一节所有适用于该环境的条件。“缺凭据”仅指空值；非空但类型或前缀不合法属于错误配置。现有 local/testing 的受限测试行为保留，不把下面 staging 规则自动用于公开本地端口。

| 环境 / 设置 | 启动 | 支付行为 |
|---|---|---|
| local/testing；受限本地规则满足 | 沿用现有行为 | 仅明确 stripe_test 可调测试 API；普通运行无假付款按钮 |
| staging；公共安全条件满足；公共开关关；driver=unconfigured | 允许 | 官方操作 503；可展示真实既有订单、权益及“未配置” |
| staging；公共开关关；driver=stripe_test | 拒绝 | 即使绕过启动检查，Gateway 仍 503，零 HTTP |
| staging；公共开关开；driver=unconfigured | 允许 | 官方操作 503，不因开关自动配账号 |
| staging；公共开关开；driver=stripe_test；任一测试凭据缺失 | 允许，但诊断为未配置 | 所有官方支付读写及 webhook 503；checkout 不建订单或占位，不假接收通知 |
| staging；公共开关开；driver=stripe_test；配置符合要求 | 允许 | 仅准入官方测试流程；有效格式不等于账号已认证或官方测试通过 |
| staging 公共安全条件不满足；或非空凭据错误、API/端点错误 | 拒绝 | 存活进程运行时再检查并拒绝，不能发 HTTP |
| production；driver=unconfigured；公共开关关；现有生产安全条件满足 | 允许 | 不允许 Stripe 调用；读取既有权益不依赖支付账号配置 |
| production 下 stripe_test、任何 live driver/key，或公共开关开 | 拒绝 | 不存在正式收费通道；直接实例化 Gateway 也拒绝 |
| 未知环境名、未知 driver、非法布尔配置 | 拒绝 | 不以“不是 production”作为放行理由 |

上述“官方操作”指需要 Stripe 通信的操作及通知接收，不封锁站内报价、后台价格配置、本人订单或权益读取。支付服务运行时拒绝沿用 `DEPENDENCY_NOT_READY` / HTTP 503，向浏览器只给安全的未就绪说明。启动失败使用固定安全诊断，不输出配置值或凭据。已发送请求后发生超时/配置变化属于未知结果：保留原 pending/占位和核对路径，不能假称已取消或清空后重建。安全审计可记录固定失败码；不生成成功付款、权益或 PaymentSettled。

## 4. 请求 00 提供的公共依赖

以下名称均为建议，须由 00 发布后才能成为正式依赖；03 本轮不创建公共类或配置。

| 建议接口 / 配置 | 责任与语义 |
|---|---|
| `App\Support\RuntimeEnvironmentGuard::assertSafeRuntime(): void` | 00 所有；校验公共环境白名单、配置类型及安全条件；不合格抛安全配置异常。无网络、无支付密钥、无永久缓存“已通过”结果 |
| `RuntimeEnvironmentGuard::controlledStagingOrigin(): string` | 每次自行调用 assertSafeRuntime 重新校验；只在环境精确为 staging、开关明确为 true 且公共条件齐备时返回规范 origin，其他情况抛异常；不能返回空值让调用方继续 |
| `H5_CONTROLLED_STAGING=false` → `h5.controlled_staging` | 唯一新增的公共准入开关，默认关闭；配置加载后必须是严格布尔值，不能将字符串 false/junk 按非空转真；非 staging 开启为错误配置 |
| `APP_URL` | 唯一规范 origin，无第二份由浏览器提交的 origin；HTTPS、明确域名、仅默认 443、无 userinfo/query/fragment/非根路径，拒绝控制字符及混淆地址；真实域名由 00/06 部署清单确定，不自动采购或猜填 |
| `APP_ENV` / `APP_DEBUG` | APP_ENV 精确 staging 且运行容器环境与加载配置一致；debug 必须严格 false。未知环境别名不兼容放行 |
| 本地专用设置 | staging 的 H5_SIMULATION=false、H5_LOCAL_US_TEST_REGION=false、H5_LOCAL_MODULES 为空；不得以本地模拟提供真实通知、地区或邮件事实 |
| session / mail | SESSION_SECURE_COOKIE=true，保留 HttpOnly、SameSite 与隔离 cookie；使用批准的真实邮件传输配置。禁止 preview/log/array，包括 failover/roundrobin 的降级路径；邮件传输配置合格不等于已证明送达 |
| 既有 `RegionResolver` / `ResolvedRegion` | 保持契约 1.0.2；staging 购买要求 `country_code=US` 且 `source=trusted`。unresolved 或伪造来源返回现有 REGION_BLOCKED/403；03 不实现信任链，不增加测试地区枚举 |

00 在 AppServiceProvider::register 注册公共依赖，再装载模块；公共 Provider 启动时检查通用规则。03 在 Billing 内增加无状态的内部策略（建议 `Support/BillingRuntimePolicy.php`），Provider::boot 与 Gateway::assertAvailable 共用它，后者必须在每次调用/验签前重新读取当前进程配置。staging 缺少公共依赖必须拒绝，不能回退到 local 判断。Billing 内部将公共配置异常转换为既有服务未就绪错误；启动仍拒绝不安全配置。返回 origin 只证明配置合格，不证明真实 TLS、代理、邮件或回调已经通过外部验收。

本提案不修改 BillingService、MembershipReader、PaymentSettled.v1、HTTP DTO 或错误枚举，也不申请迁移。公共 PHP 支持类和配置的最终命名、契约文档版本及发布提交均由 00 决定；如 00 需要改变 ResolvedRegion 的来源语义，应另行冻结，03 不自行扩大 trusted。

格式合法但被 Stripe 拒绝的密钥无法在离线启动检查中识别，不能承诺零 HTTP 或已经认证成功。实际调用失败仍按安全错误/未知结果处理，不清除原占位。

固定版本是本项目兼容约定，不宣称最新；请求版本与注册的 Snapshot webhook 版本要一致，不能无代码适配就改用 Thin events。[Stripe API 版本规则](https://docs.stripe.com/api/versioning)、[官方 webhook 事件格式](https://docs.stripe.com/webhooks)。

**Checkout 返回：** 新请求只用公共门禁返回的 origin，加已有 SafeReturn 的站内路径及服务端订单 ID；请求 Host、X-Forwarded-Host/Proto、return_to 中的绝对地址不能改变 origin。提交旧 checkout_request 前也必须检查两条完整返回 URL 的 origin、路径及订单关联。origin 不匹配、旧 HTTP 或不合格请求只进入待核对，不改原参数、幂等键和固定截止，不再 POST；在当前安全配置满足时允许只读查找原 Customer 下唯一 Session，但不把不安全旧 Session 链接重新交给用户。检查必须覆盖新建结果、只读找回结果，以及 BillingEngine::checkoutResult 直接返回已有 checkout_id/checkout_url 的路径；不能只检查再次提交的请求。旧返回地址、订单关联或 Checkout URL 任一不合格，沿用可空字段返回 checkout_url=null，保留原状态、占位与对账。实际 Checkout 跳转只接受官方 `https://checkout.stripe.com`、无 userinfo/异常端口；保留官方正常片段语义，不自行修改签发 URL。

**Webhook：** 保留唯一 `/webhooks/stripe`。先运行环境/凭据检查，再用原始 body、签名与项目已有时间容差验证；签名错误、过期、版本不匹配或 livemode 非严格 false 均不写 inbox。有效事件持久落地后才成功响应；inbox 幂等、平台对象二次读取、实际付款/金额/USD/账号/订单/周期匹配、D04 退款及 outbox 原子性保持。注册端点需要公开可达 HTTPS、有效证书，并支持 TLS 1.2 或 1.3；只豁免此路径的浏览器 CSRF，其他状态修改继续会话/CSRF/对象权限校验。[Stripe webhook 要求](https://docs.stripe.com/webhooks#receive-events-with-an-https-server)。

**保持业务约定：** D02 报价 30 分钟与已准备请求固定 31 分钟；F05 旧请求只读对账；F01 原价确认凭证、版本与防旧操作覆盖；D04 实际退款；首次优惠与订阅占位并发约束；未付周期不延权；PaymentSettled 的 is_test 与事件幂等全部不变。门禁失败不释放未知付款的占位、不延长期限、不伪造成功。广告发送失败仍不影响付款入账。
