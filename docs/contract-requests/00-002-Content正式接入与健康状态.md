# 00-002 Content 正式接入与健康状态

状态：00 接收时发现并修复，随共同契约 1.0.2 发布。

- 原版本 1.0.1：Health 把 content 等尚未实现的模块限制为 `not_ready`。正式装载 Content 后，真实 `/health` 返回 `ready`，现有 HTTP 契约校验因此失败。
- 修复：Health 的每个已登记模块允许 `ready` / `not_ready`，仍要求全部既有字段，禁止额外字段。状态来自真实装载配置；不引入自动回退或虚假成功。Content 绑定真实提供方，账务、网站、投流继续未就绪。
- 消费者：00 运行检查、各模块开发环境、06 部署检查。所有消费者同步到 1.0.2 后校验；1.0.1 的 Health 校验器会拒绝新就绪状态，不能直接当作兼容成功。目录、播放、支付业务 DTO 和 PHP 方法签名均未改变。
- 验证：保留原基础健康样例，增加 Content 已接入样例及错误状态反例；真实 HTTP 按新 schema 验证。新增 AcceptedContentTest 核对默认装载、实际数据库读取、未知地区拒绝、任务仅注册一次、未接入账务仍 503。
- 旧基础测试中把 Content 永久当作未接入的断言同步调整：缺失提供方测试显式构造缺失状态；游客入口测试读取真实地区拒绝。Identity 业务实现不变。

这次接入不表示 D03、真实会员、Stripe、真机、外部视频或正式收费验收完成。旧标签保持原提交，不移动。
