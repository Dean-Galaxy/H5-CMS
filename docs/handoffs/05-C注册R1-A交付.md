## 实际完成

- 三张独立R1表保存必要proof、两用途选择及operation回执；所有新增证据明确is_test，allow记录当时的策略/notice与合成有效期。owner仅用于选择证据权限，不含C主体、会话、事件或订单引用。
- GET只读，不创建/延长C或R1 proof，不发R1 Cookie。显式变更成功才签发随机UUID的HttpOnly/Lax必要proof，HTTPS下Secure；proof创建后绝对24个月，两用途证据都不超过其剩余上限。读取、重放、unchanged及后来另项修改不延长该proof。
- allow须01真实当前web身份及有效的独立合成选择策略；员工身份/伪viewer不够。allow只对原当前账号可见，换号或未登录读为unknown，保留真实revision作CAS；deny是当前可识别浏览器的必要退出，匿名也可保存。
- account_link与advertising独立revision和保存点；R1 capability只有unavailable/choice_only，effective始终false。site deny单独保持，其他选择不解除原C拒绝、不写旧analytics grant，不创建C账户边/付款来源映射。
- `legacy_advertising`单独映射旧选择只读，不作为本次新notice grant；新advertising allow不调用旧grant。新deny同步撤回当前可识别的旧privacy/来源并留下必要停止标记；旧付款快照不重写。
- 新旧广告写统一R1 scope串行锁：旧deny推进相应用途版本；旧无CAS allow受R1停止标记约束。R1已deny后再选choice-only allow也不授权旧发送；关R1/切旧模式仍不能清停止约束。无R1 proof/标记的普通旧模式保持原行为。
- 旧proof识别沿已有受保护会话/证据Cookie及可信当前viewer的既存Acquisition范围，不扫描Identity/账务，也不声称清掉不可识别浏览器或所有设备。site_session退出不顺带撤广告，“全关”必须各目的分别确认。

## v3实际接口及模块内职责

| 入口 | 实际行为 |
|---|---|
| GET `/api/v3/measurement/purposes/context` | 冻结schema=3、registration-purpose-r1、c-purpose-choice-only-r1-v1、is_test/eligibility、site_session、两purposes及legacy_advertising；不回内部proof/owner/测量ID |
| PATCH `/api/v3/measurement/purposes/preferences` | 单目的5字段，JSON严格白名单/4KiB；notice/revision及UUID operation校验；saved/unchanged＋当前真实state |
| 幂等与CAS | operation先锁、scope后锁；回执最多24h。同scope/身份/内容重放只确认原操作，返回当前state，不复活旧allow；同key异内容/身份或过期revision为409，notice冲突也409且回真实state |
| 失败与预算 | 401/403/419/422/413沿原保护；503 PURPOSE_UNAVAILABLE/DEPENDENCY_NOT_READY不假保存。R1独立120/IP读，30/必要session与180/IP写，429/Retry-After；不消耗v2必要退出额度 |

`site_session.effective`按v2原值复制为on/off；两新用途effective为boolean false。匿名可读能力，已有选择的scope隔离仍执行。503使用统一错误回执，不把无法读取的状态伪造为已保存；分项失败不回滚已保存另一项或必要账号。

供00后续PHP facade适配的模块内方法（不是已发布共享端口）：

- `Registration\PurposeStore::context()` / `change(purpose, choice, notice, revision, operation)`：实际scope/策略/事务/CAS；冲突携当前state，存储异常事务回滚，HTTP层返回安全503。
- `Registration\RegistrationObservations::capture(PurposePolicy::NOTICE)`：必须现有C已on、R1独立策略有效、结果开关显式true及对应R1 notice由可信调用方交付；默认/缺版本/旧版本返回null。不能只因选择库就绪自动收结果。
- `record(capture, registration_succeeded|registration_failed, failure?)`：仅同一请求、同C能力及版本，随机服务端请求UUID去重；失败限validation/conflict/temporary/unknown。不接viewer/email/session摘要key，拒绝序列化为身份→C重试映射。
- 结果入C原始表时使用R1策略/notice元数据、is_test=true，没有基础身份/订单字段。Accepted含同内容重放；拒绝/结束/未准入Skipped；临时失败保存点回滚后Retry，调用方不得把它反向改成认证失败。浏览器同名成功/失败事件仍422，登录/Verified等本批不开放。
- 退出/换号沿原clearBrowserContext结束职责，保留必要拒绝；R1没有可运行的账户附着。01-B实际捕获时序、来源事实及返回处理仍须00公共端口与适配后组合验证，本批未接真实01钩子。

## 默认配置与清理

00的`H5_C_REGISTRATION_ENABLED`默认false且受Guard限制；选择另用本模块默认false的`ACQUISITION_R1_SYNTHETIC_POLICY`及`ACQUISITION_R1_SYNTHETIC_FROM/UNTIL`。服务器要求起止为合法带时区ISO绝对时间、已开始未过期、实际秒数最多86400；相对时间/无效日历值拒绝，且仅local/testing、模块就绪及C体验/R1开关都开启；不继承旧站策略或用US测试区当资格。

`ACQUISITION_R1_OBSERVATIONS_ENABLED`另默认false，只用于模块内受信注册结果，不能授选择/账户/广告权限；本批HTTP没有启用它，仅专项显式开启验证。非local/testing拒绝这些合成/结果配置；未放宽公共Guard。原.env字节未改，原服务未启R1，外发disabled。

`acquisition:r1-prune --limit=1000`有界清过期operation及proof（级联自身选择/回执），不删原账务/来源、旧拒绝证明或C轨迹。operation到期后不作旧幂等确认，proof到期不再用于选择回读。R1开关true时登记每日清理；**关开关不等于完成物理清理**，先前测试数据仍需00/06安排独立清理并验收到期，备份恢复不复活另验。只在冻结时钟下验证清理，不宣称已实跑24个月或完整权利删除系统。
