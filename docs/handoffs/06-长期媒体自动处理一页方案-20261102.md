# 06 长期媒体自动处理：一页审阅方案（仅方案）

**结论：复用现有CLI＋原生systemd，每次处理一项；不把45分钟验收监督器扩成长期框架。** 本轮仅提交本文，未创建下述unit/脚本、修改业务、安装启用、领取素材或调用云API。00回执本轮3/3及前轮7/7已通过并在备份关窗；这证明受限验收可用，不等于长期后台已运行。应用仍57a658ef；本机a509工作区所读三份媒体模块源码与57a差异为空。

| 实际缺口 | 最小决定 |
|---|---|
| 新上传还需人工定点处理；`queue:work`不负责这条同步媒体链；现`schedule:work`同时调发布等任务 | 单独执行现有 `php8.4 -d memory_limit=128M artisan content:process-media --limit=1`，不启动通用queue/scheduler/发布/账务/广告。素材ready后仍须原生确认和保存，不自动发布。 |
| CLI对failed也可能退出0，systemd无法辨认业务失败 | 由00派02最小修正：空队列/实际ready退出0，返回非ready或处理异常非0；保留现有安全状态输出及所属专项。不在ops另造业务解析器；**该修正未实施前不能声称失败自动停机覆盖完整**。 |
| 领取没有Owner/hash/新旧过滤 | 默认领取最早pending及租约过期processing；首次启用前00只读列存量并取得处理范围。**不能拿45分钟/6条许可覆盖不限次数、所有上传账号或旧任务。** 若需排除旧pending而继续领新，现CLI做不到，先交02确定筛选规则，不在ops藏排除清单、改时间或删记录。 |

**下一实现候选的明确文件（现在均未创建）：** `deploy/h5-media-process.service`、同名`.timer`、`deploy/h5-media-stop-on-failure.service`，以及06的unit离线专项；02另改原 `ProcessMedia.php` 和所属测试。默认不安装、不enable，root持有的 `/srv/h5/ops/media-process/ENABLED` 缺省不存在；service和timer均以该标记作启动条件，应用h5无权自行开启；根持有RUNNING标记在领取前创建、仅CLI成功后删除，残留则阻断下一次执行/重启，避免断电绕过故障暂停。不复用45分钟binding/额度台账，也不建新库、迁移或换APP_KEY。

| 生命周期 | 候选行为（实际Linux支持和效果待验） |
|---|---|
| 正常运行 | `Type=oneshot`、`Restart=no`、h5用户、固定 `/srv/h5/current/h5-platform` WorkingDirectory；先核staging/缓存及数据库已运行。timer每分钟UTC一次，AccuracySec=1s、Persistent=false；同一service未结束不另起一份。切版/人工定点处理前先停timer及在途组，禁止另开领取进程。 |
| 资源与失败 | 初始建议PHP128M、CPUQuota=50%（一核的一半）、MemoryMax=384M、TimeoutStartSec=15min、KillMode=control-group、TimeoutStopSec=5s；这是当前约939MiB/无swap主机的待测起点，不是容量承诺。oneshot用TimeoutStartSec，不能用RuntimeMaxSec冒充超时限制。非0/超时/OOM触发第三个原生oneshot：仅删除固定ENABLED标记并停止本timer，不动其他服务；失败保持关闭，不能自动风暴重试。 |
| 任务与恢复 | 现MediaStore有20分钟processing租约、最多3次实际尝试；正常failed不自动领取，异常中断可能在租约过期后重领。15分钟进程上限低于租约，但现视频多步骤总超时可能远超15分钟，需代表性素材验证；超时先保留状态/部分产物并停，不重置attempt/租约或删文件。00先查清未知状态；确认可按既有租约重领且属于**获准原范围**才恢复，不自动重试未知任务。 |
| 开机和停止 | 只有本人另准长期启用/开机恢复后才enable timer。数据库仍按原站点策略：DB未运行则ExecCondition跳过、下分钟再检查，**worker不自动启动PG/FPM**；若要整机重启后无人干预恢复，须另批准PG启动策略。故障删除ENABLED或断电残留RUNNING时，重启都不自行解锁。维护/关窗先停并disable timer、去标记，再停service并核PHP/FFmpeg组清空，随后由00备份和精准关站。 |
| 权限与费用 | 预建并核对config/packages/services缓存；媒体可写，复用CLI的Console Kernel会报告未捕获异常，现daily日志需最小 `shared/storage/logs` 可写，根标记目录仅供固定root touch/rm步骤写、h5仍不可写，不开放全部storage/shared/bootstrap/cache。只用现主机，CPU/磁盘/既有额度增耗需观察，不能承诺零费用；不采购/升级/自动扩容，不自动清理业务媒体。磁盘水位、日志保留和接收人未闭环前，只算有人值守测试版。 |

原生行为依据：[timer不重入及定时语义](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html)、[oneshot启动超时与停止](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)、[CPU/内存限制](https://www.freedesktop.org/software/systemd/man/latest/systemd.resource-control.html)。这些是设计依据，**不是本服务器已验证**。

**新授权必须明确的范围：** 单一现有staging长期处理哪些上传账号的新任务、是否包含核过的存量pending/过期processing及现有重领；不再受45分钟/6条/合成SHA限制；允许安装/持续timer/故障暂停/同范围运维恢复，是否开机启用；PG自启仍另列。保留现有库/Owner/MFA/APP_KEY及公网维护；不包含FPM/公网开放、发布/付款/广告、资源采购或删除素材。本轮不向本人发抽象许可题，由00拿冻结候选合并必要决策。

**新增验收条件：** 离线先证默认关闭、CLI失败非0、只含media入口；授权后00实核①空队列无业务变化、新上传仅一项一项ready且无重入；②非ready/超时后timer停、标记撤、子进程清空、attempt未被重置；③按已批准PG策略重启后只恢复应恢复部分，故障保持关闭；④代表性素材的内存/CPU/磁盘和后台响应可接受，指定接收人实际收到一条获准故障告警。复用已过封面保存/内部预览和全库恢复证据，不要求本人重复10项，不把旧证据当新worker通过。

**邮件仍未验：** SES沙箱解除/正式区域发送范围及额度尚未获批或验证；原真实验邮仅适用于已验地址和受限窗口，不等于任意邮箱可收。SNS退信/投诉通知的签名、订阅、实际收件、抑制/停止发送和责任人处置闭环，以及磁盘/worker失败告警到真人均未验；先核现有SES/通知能力再申请必要最小接入。不自建邮件平台，不发新信、不建SNS、不扩大SMTP/IAM或购买资源。
