## 实际实现与调用接口

| 接口 | 实际行为 | 限制 |
|---|---|---|
| `PaymentLedger::record(string $subscriptionId, ExternalPayment $fact): string` | 同一事务核对scope、账号/原订单、订阅/客户、原价/金额/币种及原始周期，再写唯一付款、对应权益区间、首惠使用、订单和PaymentSettled.v1 outbox。返回站内payment UUID；重复不再写，不复活已退款权益。Stripe成功付款已改用该唯一写入入口 | 这是模块内部接口，不是HTTP接口；只能由服务器付款验真器调用。类型不是官方验真证明。本段PayPal调用仅有testing夹具，未把未核实Sale/通知直接传入 |
| `ExternalPayment` | 带ProviderScope的内部付款事实，表达外部付款/扣款引用、所属原订阅/订单、是否初始周期、金额、USD、明确的起止与付款时刻 | 禁止用now()+7d构造周期。PayPal实际交易/周期读取适配器尚待实现；无法唯一归属的事实必须核对，不能由浏览器提供 |
| `ProviderGatewayRouter::forRecord(object): PaymentGateway` | 以持久化provider/environment/merchant_scope选择适配；新购配置不会改变既有对象所属。当前原Stripe scope使用旧适配；PayPal与未知商户明确DEPENDENCY_NOT_READY，无默认降级到Stripe | **尚未注册PayPal付款/周期适配器**。当前router具备隔离、防误派和扩展接点，不代表两个渠道均可运行 |
| `ProviderInboxStore::receive(ProviderScope, array $event): string` | 只在上游验真之后持久化最小事件引用；相同scope+event ID重放不重复，不同商户或渠道相同ID不冲突；相同ID不同对象/类型/时间拒绝覆盖 | 不保存原始body、签名、token或付款人资料，不把收件成功当付款 |
| `PayPalWebhookReceiver::receive(string $rawBody, array $headers): string` | 候选配置读取后构建原始验签请求，官方验签协议返回SUCCESS才写scope inbox；失败/未知不落收件。读取与写入之间配置变化拒绝。环境来自固定sandbox客户端而非入参is_test | 仅内部类，**没有新增公开路由**。官方调用当前仅MockHandler隔离测试，真实验签仍未验 |
| 旧`WebhookService`、`BillingEngine`、`billing:reconcile` | 旧Stripe通知/操作/对账加入scope范围和派发检查；PayPal已识别事件在处理器未完成时保留pending/RECONCILIATION_REQUIRED；不支持的一次性Orders Capture事件忽略，不开会员。PayPal恢复入口保持关闭 | 已收到的PayPal事件不能误走Stripe并标processed；公开PayPal收件入口还不能放行 |

本段把Stripe原来的成功付款写入提取到同一PaymentLedger，未复制会员判断或PaymentSettled事件格式。MembershipReader继续读原billing_entitlements，Content/Audience无需另维护会员。广告消费仍通过可靠outbox，付款写入过程没有广告平台调用。

历史列名`billing_payments.provider_invoice_id`为兼容保留：在scope=paypal时它保存Sale付款引用，**不声称PayPal存在Stripe invoice对象**。任何读取必须同时带scope；后续展示以通用“平台付款编号”说明。现有Billing后台不直接暴露该列。
