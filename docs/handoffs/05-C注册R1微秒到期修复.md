## 问题与最小修复

Laravel/PDO把DateTime SQL绑定降到整秒，R1虽以6位小数写入expires_at，查询若直接绑定now()则可能把非整秒到期误判至该秒结束。沿用本模块既有Analytics/Clock::stamp文本封装保留UTC微秒，比较符和事务语义保持：

| 文件 | 修复边界 |
|---|---|
| Registration/PurposeProof.php current | expires_at > Clock::stamp()；[from,until)的until到点不可用 |
| Registration/PurposeStore.php change | 按operation_id删除expires_at <= Clock::stamp()的旧回执，再走原身份/政策/CAS；旧allow不绕过当前deny |
| Console/PruneRegistrationPurposes.php | operations、proofs两处expires_at <= Clock::stamp()；原批量上限、事务、级联保持 |

审计Registration下所有SQL及该清理命令，确认只有以上4个同类SQL到期边界；写入原已用Clock，未另改纯PHP Carbon精确比较（PurposePolicy、LegacyAdvertisingBridge、Cookie期限、24h回执上限）。未改旧v1/C算法、D05、旧同意/拒绝、外发或业务规则。

注意：过期回执在成功的当前命令事务中被清理并替换；请求若因CAS/身份等失败，删除仍随原事务回滚，不声称所有失败请求都会留下物理删除。未到期同操作重放仍只确认原操作及当前真实state，不能使旧allow重生；到期后旧命令必须重新通过现有验证，后台prune另负责物理清理。
