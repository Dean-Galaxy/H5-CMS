## API、通知与补偿

复用PayPal REST：OAuth2 `/v1/oauth2/token`，Catalog Products v1，Billing Plans/Subscriptions v1，Notifications/Webhooks v1，原Sale/Refund读取v1。PayPal不采用Stripe日期版本头；Stripe原锁定`2026-08-26.dahlia`不变。无新增退款发起、补扣或activate接口。当前[REST官方说明](https://developer.paypal.com/api/rest/)、[正式环境切换](https://developer.paypal.com/api/rest/production/)、[订阅API](https://developer.paypal.com/api/subscriptions/v1/subscriptions-create/)、[通知验签](https://developer.paypal.com/api/rest/webhooks/rest/)已核；使用官方批准链接，固定正式域名和证书主机，不请求通知里任意URL。

| 通知 | 站内处理 |
|---|---|
| PAYMENT.SALE.COMPLETED | 核Sale→所属订阅、Plan、完整交易及稳定实际周期→唯一付款与权益；按原订单区分首购/再次订阅/续费 |
| CREATED/ACTIVATED/UPDATED | 仅触发读回与核账；ACTIVE本身不授予权益 |
| PAYMENT.FAILED | 读回失败/欠款，保留原已付款区间，不延长；到期只免费内容 |
| SUSPENDED/CANCELLED/EXPIRED | 按当前官方状态核对停止未来续费，保留对应已付区间，乱序不按通知标题盲改 |
| SALE.REFUNDED | 查实际Refund及Sale累计；部分退款保原期/停续费，累计全退只撤对应付款权益 |
| SALE.REVERSED | 待人工核查并保持停续费意图，不伪造退款或恢复 |

重送通知按环境/商户/event去重，只存必要引用。补偿仍用原 `PayPalReconciliation::sync(站内订阅ID, allowLifecycleChanges:false)` 定向官方读回；这不承诺退款读取完全无副作用。已核准当前环境窗口才跑`billing:reconcile --limit=...`，会处理当前环境账务/待操作/退款及outbox，不能对未获准旧A/B/C使用。停止新购只改新购选择；临时停止API须同时把新购改回unconfigured，保留账本、权益及待发/待核，不回退有Live数据的迁移。恢复由00按原对象复核重试，不重建订单。
