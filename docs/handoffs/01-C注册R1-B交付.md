## 实际实现

### 同请求最小注册结果

- R1 GET注册页真实构造/渲染告知后，才在受保护的服务器会话保存已交付版本 `c-purpose-choice-only-r1-v1`。POST隐藏notice、旧版本、未显示页面、普通模式都不能凭自身触发捕获。仅保存版本，不保存捕获对象、测量key或账号到C的映射。
- 新RegistrationObservation只依赖实际公共 `RegistrationMeasurement`、marker及RegistrationResult。当前请求在必要建号前capture；账号与必要收据事务正常返回后立即记录 `registration_succeeded/failure=null`，先于Registered/邮件及自动Login清旧C的窗口。失败仅validation/conflict/temporary/unknown，无表单、邮箱、viewer/session摘要或任意properties。
- 记录端availability/capture/record抛错、不可用、空capture、Skipped/Retry全部与必要身份结果解耦。每实例只结束一次，结束清除端口/capture，序列化抛异常；不创建持久重试或补历史机制。已提交账号的邮件失败仍是注册成功，不重发建号。没有新增登录/Verified C事件。
- 默认公共绑定仍为00的DEPENDENCY_NOT_READY，真实05提供方尚未在该基线绑定。本轮PHP替身只证明消费时序、最小数据及故障隔离；真实C/策略/拒绝复核由05提供方和后续组合验证，01没有读取05私有表、Cookie或模块内服务。

### 两项独立选择

- 初始无默认允许，GET真实context后才按capability启用；已有真实choice可回读，旧独立advertising allow不勾选新用途。分别显示choice、effective/off及reason，site_session状态和旧独立广告状态另列。保存选择不宣称关联或广告已运行。
- 必要注册响应明确成功，或回程未知后现有me确认同一表单身份，才进入独立用途阶段。只提交dirty项；未动/缺省为客户端not_requested，不把未勾选补成统一拒绝，不向注册POST夹带可选选择。
- 每项命令只有purpose、choice、notice_version、expected_revision和独立UUID operation_id。每次提交/显式重试均先用现有me核同一账号，再刷新原csrf端点令牌；不传viewer、邮箱或actor给目的接口。两项结果分别显示saved/unchanged/unconfirmed/conflict，重试按钮标用途名称。
- 503、丢响应或无法解析保留本页内存草稿和同一operation_id，显式重试该项；已成功项不重发。409使用返回真实state或再次GET；确认回读才显示冲突，回读失败显示未确认。无自动重放，显式确认以新operation_id及最后已知revision提交，服务器CAS仍为最终校验。
- 身份临时读取失败只暂停，不授权PATCH；匿名/换号丢弃旧草稿、操作号及旧选择显示，并锁定本页可选提交。没有敏感本地存储。注册结果未知不重新提交密码或建号；必要账号成功后再次submit也不重复注册。
- 无JS仍正常建号并进入账号页，本页可选草稿不提交，可之后在网站隐私管理器处理；本轮不实现04全站管理器。继续按钮先到账号确认/验证页，原受控return_to仍由必要会话保留。
- 中英文说明区分必要接受、本站会话分析与两项可选用途。英文隐私页已将“by signing out”歧义改为明确“撤回不改变必要账务或已付权益”。中文并行更新；本机示例仍非正式政策。页面不主动start/allow C、不更改旧deny。
