## 复现与修复

旧submit先me核A，再取得CSRF。若期间另标签切B，取得B的新令牌后仍会提交A草稿。00私密探针只读核对、不提交；01另在自己的测试夹具先跑未修改的旧identity.js，得到 `me:A → me:A → csrf:B → patch:B/current:B`、模拟保存1条，安全断言失败。这里“保存”只是合成提供方内存数组，不是真实用户或数据库事实。旧源码摘要与该失败输出单列保留。

新顺序为：必要context读取准备→获取并固定本次CSRF→重新核对当前必要身份→只带该固定令牌发一次PATCH。身份不符即清旧草稿、旧选择显示和操作号，不发写请求；核身份后再切号不能换取新令牌继续旧意向，由旧令牌419拒绝。419提示未确认/页面过期，未报保存成功、不自动刷新令牌重放；显式重试仍走同一安全顺序。

未改当前账号可信校验、dirty项目、部分成功/未知回程、原operation幂等、necessary注册/账号结果、only-choice/effective=false或旧deny。没有新增持久令牌、身份映射或跨账号草稿。先前“me恢复不证明本次建号”的文案修正保留。
