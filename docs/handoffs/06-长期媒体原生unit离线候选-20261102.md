## 权限、顺序和持久化

1. PID1先判断标记条件。h5的ExecCondition只读PG unit状态；DB inactive等退出1–254时跳过，保留timer等下一分钟；不自动拉起PG/FPM。异常退出255/信号/超时按失败处理。unit active也不保证DB已可连接，实际连接失败仍应停机。
2. ExecStartPre先以h5检查标记目录**实际不可写**，再以root检查目录归root；随后h5运行现staging/缓存守卫。权限或守卫失败不进入媒体CLI。
3. root `touch RUNNING`，然后 GNU `sync -- RUNNING 标记父目录`；两个同步对象都成功后才进入CLI。命令失败不忽略，进入OnFailure。不是单touch就承诺断电保留，也不使用RuntimeDirectory/tmpfs存该标记。
4. 只有oneshot的CLI成功退出才执行root `rm RUNNING`，再同步父目录。**无ExecStop/ExecStopPost清标记**；在途正常stop、非0、timeout、OOM均应留RUNNING。失败unit撤ENABLED并同步目录后，发出固定timer的异步stop请求；请求返回0不是timer已停证据，00仍须核inactive和进程组。

root前后步骤用 **`!` 前缀，仅不应用User/Group凭据，保留ProtectSystem/其他沙箱**；不用`+`、sudo、shell、动态命令或用户参数。两unit均NoNewPrivileges、空CapabilityBoundingSet。media unit的RW挂载例外为media、storage/logs及root标记目录；**ReadWritePaths不授予DAC写权**，root目录0755＋root文件0600使h5仍不能写标记。新增原生检查也会拒绝h5实际可写/目录非root。持久业务目录对h5只开放原media和必要logs；PrivateTmp提供隔离临时空间。failure unit只开放root标记目录写，网络仅AF_UNIX，不接外部通知。

不放宽 `/etc/h5`、整个shared/storage或bootstrap/cache，不加sudo规则。现Console Kernel会报告未捕获异常，故只开放原 `storage/logs`；正常启动必须已有匹配的config/packages/services缓存。缓存缺失或沙箱拒写先停留首败，不在worker里重建。

**持久化限度：** 上述GNU sync带文件参数使用fsync，分别请求文件及父目录持久化；这是命令顺序和未来原生验收要求。本轮没有在源机执行sync、实际断电或验证存储设备兑现持久化。不能宣称“断电一定保留/一定防重领”；当前承诺是**检测到残留即暂停**，以及同步失败时不继续进入CLI。检测不到残留的断电情形仍是剩余原生风险，必须由00验证后决定是否放行。任一root步骤/同步/stop请求失败均需工程确认，不能自动清未知标记。

依据：[凭据前缀及oneshot成功后步骤](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html)、[RW挂载与原有权限](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)、[GNU sync的文件参数/fsync](https://www.gnu.org/s/coreutils/manual/html_node/sync-invocation.html)。文档依据不是本机原生验收。

## 生命周期及待核预期

| 场景 | 预期；本轮仅配置/夹具核对 |
|---|---|
| 缺ENABLED、或有残留RUNNING | service/timer启动条件跳过；不读素材、不bootstrap、不自动清标记。 |
| 空队列/ready且CLI0 | 同一次oneshot完成，RUNNING删除并同步；service回inactive为正常，timer保持等待下次。 |
| 非ready/异常CLI非0、15分钟超时、OOM | 成功后步骤不执行，留下在途痕迹；OnFailure撤启用并请求停timer，不重启。组内PHP/FFmpeg按control-group收尾，5秒后SIGKILL兜底。 |
| 正常stop打断在途CLI | 不走无条件清理；RUNNING留待核，下一次service或开机timer启动被阻断。完成与stop竞态须原生验证。 |
| PG停机/条件跳过 | 不拉起PG，不创建RUNNING或领取任务；有授权且原PG恢复后等下一触发。 |
| 同unit重入 | timer只指向一个非模板service，前一激活未结束不产生第二份；人工处理前停timer/service并核组清空。 |
| 断电/重启 | 只在原授权允许enable时才有开机timer；若同步后标记实际保留则阻断，不自行解锁。PG自启仍另行批准，未改其原manual策略。 |

CPUQuota=50%、MemoryMax=384M、PHP128M和TimeoutStartSec=15min是**容量待测起点**。oneshot不用RuntimeMaxSec。现处理租约20分钟、最多3次尝试；视频多步骤总耗时可超过15分钟，不能说已适用于所有真实视频。不同账号/旧pending/过期processing均可能被现CLI选中，启动前须只读清点并获准；不重置attempt/租约、删素材或偷偷加排除清单。
