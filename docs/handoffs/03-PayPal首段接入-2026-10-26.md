## 本段实际实现

| 代码 | 能力 / 当前边界 |
|---|---|
| `Gateway/PayPal/PayPalAmount` | USD十进制字符串与整数最小单位转换，不用浮点，不接受指数/负数/非USD/多余精度；上限与当前账务价格一致 |
| `SandboxWeeklyPlan` | 不可变价格快照构建测试Plan，一次付费WEEK TRIAL后无限REGULAR WEEK；老用户只REGULAR；候选auto_bill_outstanding=false、failure_threshold=1。不自行决定首惠资格，不发送请求 |
| `SandboxWebhookEnvelope` | 五个传输头和原始JSON验证请求构造；拒重复头、注入/非法证书URL/无效时间；原始body逐字保留。事件仅分类为核对线索，ACTIVE/成功回跳不转付款；回调所属webhook ID需与客户端受控配置一致 |
| `SandboxApi` | 固定sandbox主机的OAuth、查Plan/订阅、创建Plan、suspend、官方验签请求；TLS/no redirects/无自动重试，错误脱敏，配置变更丢弃旧token，非testing禁止注入替身。**未绑定PaymentGateway、没有createSubscription/activate/capture/refund/购买入口** |
| `Gateway/ProviderScope` | provider/environment/merchant范围不可变值对象，只允许Stripe test与PayPal sandbox；从记录读取，不能靠新购全局配置推测旧记录归属 |
| `Services/ProviderOperationStore` | 创建意图在发送前持久化，同owner/版本/操作重用同key/参数；未知状态先提交后发请求，72小时后只能对账；同外部ID跨渠道/商户隔离，同owner同范围不能认领第二份外部对象。该服务不写付款、权益或outbox |
| `2026_10_26_200400_add_billing_provider_scopes` | 旧账务表新增Stripe/test/legacy-stripe-test归属；新增provider_resources/provider_intents。保留原ID/金额/权益、原外部ID唯一索引、跨渠道viewer唯一进行中订阅。已有新证据时down明确拒绝，不能静默删账 |

**迁移分段限制**：本段未删除旧全局外部ID索引，也未把旧查询改为scope查询；provider_resources可隔离同名外部对象，但旧账本尚未接收PayPal付款。必须完成后续同账本适配、查询范围、兼容迁移与回归后才允许新购PayPal。不能现在只改driver启用。旧Stripe账务行为保持原实现；既有普通服务没有运行迁移，本段迁移只在03隔离测试库验证。

## 00 公共补丁精确定义

以下是03待消费字段，默认禁用；由00维护样例、环境Guard及公共说明，03维护模块读取/运行绑定。当前没有把这些值写入任何本机.env。

| 配置键 | 建议环境变量 | 类型/默认/要求 |
|---|---|---|
| `billing.paypal.enabled` | `H5_BILLING_PAYPAL_SANDBOX_ENABLED` | boolean false；凭据存在不隐式启用 |
| `billing.paypal.client_id` | `H5_BILLING_PAYPAL_SANDBOX_CLIENT_ID` | nullable string；启用调用必填，仅服务器 |
| `billing.paypal.client_secret` | `H5_BILLING_PAYPAL_SANDBOX_CLIENT_SECRET` | nullable secret；不出日志/DTO/诊断 |
| `billing.paypal.webhook_id` | `H5_BILLING_PAYPAL_SANDBOX_WEBHOOK_ID` | nullable string；真实App注册ID，不接受模拟器`WEBHOOK_ID`作正式验证 |
| `billing.paypal.merchant_id` | `H5_BILLING_PAYPAL_SANDBOX_MERCHANT_ID` | nullable string；后续付款验真匹配收款方，非浏览器字段 |
| `billing.paypal.merchant_scope` | `H5_BILLING_PAYPAL_SANDBOX_MERCHANT_SCOPE` | 稳定非敏感别名，1–64位小写字母数字/下划线/连字符且首位字母数字；换商户必须另scope，不能改旧对象所属 |
| 后续 `billing.new_purchase_provider` | `H5_BILLING_NEW_PURCHASE_PROVIDER` | unconfigured/stripe/paypal；本段不消费，必须等provider路由串接；不能覆盖已存对象scope |

不新增可覆盖API base或“已官方通过”环境开关。产品ID由不可变Plan创建调用参数提供，后续可由03的受控配置/资产映射存储，不从浏览器收取。恢复能力在取得官方证据前不开放，不提供自行勾选跳过验证的开关。

受控环境要求：local/testing与00明确受控staging；生产拒绝，staging仍遵守当前controlled_staging/HTTPS origin/可信地区。真实账户sandbox凭据由07引导本人配置；商户主体/国家/Business类型尚未知，不能套用另一个项目的中国内地主体信息。

公共路由：未来仅增加 `webhooks/paypal` 精确CSRF豁免；03自身路由保存完整raw body和五个header数组，调用Envelope→SandboxApi.verify；SUCCESS且inbox可靠落地才2xx，失败/未知不确认收件。不扩大billing浏览器CSRF豁免。**本段没有listener/inbox接线，00暂不可把公开路径当ready**。

`Checkout.expires_at`已经nullable，无需现在增DTO；D02 PayPal专项使用null表示平台截止未知，另存站内31分钟停止提供链接期限，不能写成平台绝对过期。04需空值处理和清晰提示；F01原价凭证字段不变。PaymentSettled.v1/MembershipReader继续唯一来源，01/02/05无需另建状态或支付入口。
