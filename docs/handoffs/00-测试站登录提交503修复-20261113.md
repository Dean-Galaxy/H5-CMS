# 测试站登录提交 503 修复

2026-11-13，北京时间。本人报告输入账号并点击登录后出现 Nginx 503。当前应用仍是正式站 77d28d15、独立投流测试站 54171117；本轮只修独立测试站边缘配置，不开广告、支付或邮件。

原因：IdentityServiceProvider 通过 Livewire::setUpdateRoute 将登录页实际提交地址设为 /admin/livewire/update，登录 HTML 的 data-update-uri 也明确声明此路径。此前按 route:list 找到哈希 update 路径就将另一路径当成旧别名，模板仅放行哈希路径。页面与静态文件虽然返回 200，真实登录提交仍被 Nginx 拦成 503。00 对此前验收漏掉提交动作负责。

修复：只新增 POST /admin/livewire/update 精确白名单，复用原 FastCGI、会话、CSRF、账号与 MFA 校验。其他路径默认关闭；原哈希兼容保留。原生 nginx -t 和实际 reload 通过，正式四项应用/邮件/站点/pool 配置摘要保持。

实际验证：

- 同一个不带 CSRF、无账号资料的空 JSON POST：修前 503，修后由应用返回 419。
- 干净原生 Chrome 输入明确不存在的合成账号并真实点击登录，实际 Livewire Fetch 返回 200，页面内显示“登录信息有误。”，无 503 覆盖层或脚本异常。没有使用本人的真实密码或 MFA，没有创建账号或发送平台事件。首轮断言未匹配实际中文提示，已按保留的 DOM、请求状态及截图核实，不放宽账号校验。
- 正式与测试站 GET /admin/login 均为 200，测试页未登录仍跳同站正常员工登录，无浏览器 Basic 小窗。本人真实 Owner/MFA 登录成功仍待反馈。
- 变更前配置、变更后配置和回执共 3 件已 age 加密离机，认证解密及逐 SHA-256 核验通过。私密证据位于 .runtime/00-staging-login-20261113/，不发布真实 HTML、CSRF、Cookie、凭据或 MFA。

以后后台入口验收必须从实际页面提取提交 URL，并真实点击至少一次合成错误登录，确认请求进入应用并在页内给出校验提示。GET 200、脚本 200 或 route:list 中存在一个更新路由都不能代替这一步。完整有效账号/MFA 成功仍由本人确认，不能用合成错误登录冒充。
