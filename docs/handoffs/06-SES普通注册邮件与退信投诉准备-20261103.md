## 最小配置草稿（未应用）

| 配置 | 保留/下一步 |

| 应用 | 保留 APP_ENV=staging、现有 HTTPS 私密入口、普通注册与现有节流；不启用 R1/增强采集，不改为 local/testing，不启通用队列 |
| SMTP | 保留既有私密 mail.env、区域端点和 TLS/证书校验、固定 From；不生成新密钥，不打印密码，不把 SMTP 受理写成邮箱投递成功 |
| 身份/配置集 | 沿用已验证域名和默认 my-first-configuration-set；授权后确认实际发送仍采用该配置集，以及未覆盖取消 BOUNCE/COMPLAINT 抑制 |
| 反馈首选 | 沿用已启用 Email Feedback Forwarding。先核实际 SMTP MAIL FROM/Return-Path 的接收地址及真实邮箱，再用模拟器验证退信和投诉各到达一次。SMTP 未设 Return-Path 时反馈走 MAIL FROM；当前代码没有自定义 Return-Path，实际 envelope 仍需在私密回执核实 |
| 反馈备选 | 若上述邮箱不可收信或无人值守，先查是否已有同区域主题可复用；必要时提议一个 us-east-2 Standard SNS 主题、一个已确认的运营邮箱订阅，在身份 Notifications 绑定 Bounce/Complaint。仅需要投递事件证据时另加 Delivery；无需公开 HTTP 回调、点击/打开追踪、应用抑制表或邮件平台 |
| SNS 权限草稿 | 仅主题资源策略允许 ses.amazonaws.com 对该主题 sns:Publish，同时限定本账户 SourceAccount 和 `arn:aws:ses:us-east-2:<ACCOUNT_ID>:identity/sparklingshort.com` SourceArn；真实值私密绑定。若现有独立邮箱身份生效，须核其覆盖并对实际身份配置，不盲目只改域名。配置由获授权工程主体执行，不授 SMTP 用户 SNS/SES 管理权 |
| 普通收件权限 | 生产访问获批后，另交00审阅现有 SMTP 策略：保留单一 From、TLS、SendRawEmail 与既有精确资源，只按批准范围调整测试收件人条件/测试身份资源；不能仅删一个条件就假定所有策略均放行。小批受控测试可先维持明确名单；普通用户全量开放须本人另准 |

原生通知选择依据：[AWS 邮件反馈路由](https://docs.aws.amazon.com/ses/latest/dg/monitor-sending-activity-using-notifications-email.html)、[SNS 身份通知与主题权限](https://docs.aws.amazon.com/ses/latest/dg/configure-sns-notifications.html)。默认先复用邮件转发；SNS 为有证据需要时的备选，尚未建资源/新增费用，具体创建和费用由00再核准。

账户抑制可让 SES 接受请求后停止实际发送，不能通过 SMTP 返回成功认定已送达。反馈收到后，由指定负责人识别硬退信/投诉，保持对应地址抑制、不安排重试或随意删除；收件人主动纠正邮箱后才按既有验证流程处理。软退信不做盲目循环重发；持续异常时由00暂停发信入口、保留账号和证据，调查后恢复。反馈含个人信息，完整内容仅私密留存，公共交付只列时间、事件类型和去敏关联结果。此为待确认的处理流程，不是已运行SLA。[AWS 抑制与配置集覆盖规则](https://docs.aws.amazon.com/ses/latest/dg/sending-email-suppression-list.html)

## 下一授权窗口的验收与停止

1. 00串行安排；先只读核 us-east-2 当前沙箱、额度、域名/独立邮箱身份通知、默认配置集/覆盖、账户抑制与 SMTP 策略。遇到与历史回执不同则停在首差异，不凭本稿覆盖。
2. 在明确的新发信/必要配置授权内，最多先做硬退信、投诉各1封官方模拟器，保存 SES messageId 与反馈到达/负责人确认的关联；两封不属于此前本人两封网站邮件的剩余额度。模拟器硬退信不会实际把模拟地址加入抑制列表，所以不能据此宣称真实地址抑制自动入列通过；需要该证据时另约受控用例。
3. 反馈闭环、真实申请资料齐备后提交申请，记录审核结果；在此之前普通用户发送仍未就绪。取得批准与独立收件权限许可后，只做必要受控注册/验邮与找回密码真实收信验证，区分 SMTP 受理、收件服务器 Delivery、本人邮箱收到和链接使用成功。
4. 应用现有同步 SMTP 故障恢复已审读：注册邮件传输不确定保留新账号，重发/改错邮箱有节流，找回密码统一响应；验证链接30分钟、nonce/签名/账号绑定且一次使用。本轮未发现需要新增业务实现的证据，没有重跑原01测试或改代码。`verification.sent` 审计仅表示通知调用返回，不是投递结果。
5. 失败时保留首个拒绝、通知与 IAM 差异；不切 log/preview 假报真实发信成功，不取消抑制或自动扩大收件权限。00决定暂停发信/回退相关配置；保留新增注册与验证事实，不回滚整库。现有媒体日常服务和公网503不受本离线稿变更。

模拟器范围依据：[AWS 官方模拟器说明](https://docs.aws.amazon.com/ses/latest/dg/send-an-email-from-console.html)。本轮完成的是源码/历史回执与官方语义核对、配置及申请草稿；SNS接收、真实退信投诉、脱沙箱批准、普通用户邮件和密码重置收信均未执行、未记通过。
