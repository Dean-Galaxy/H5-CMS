## 实际行为

- `h5.measurement_c_experience === true`时，旧浏览器Recorder及01/03调用的旧服务端分析Recorder明确返回`Skipped`，不产生分析重试；C关闭、策略未知/过期、读取故障都不能退回旧分析。`TrackingContext.enabled()`仍服务独立广告来源，未把整个Acquisition强行关闭。
- 新模式下旧正向analytics请求不能新授旧分析权限；已存旧选择保持真实历史，明确拒绝才变为denied。不会新建旧分析subject、viewer关联或订单映射。原模式无C拒绝时保持原行为。
- C `site_session=deny`在同一数据库事务中结束C能力，并把**可识别的既存Acquisition隐私证明**的分析状态改denied、清分析grant时间与当前subject，增加必要拒绝时间/到期字段。识别只使用受保护旧proof/session、最多20项旧证据Cookie和IdentityContext提供的可信当前身份所对应既存proof；不扫描身份表，不接受浏览器viewer，不保存C主体与账号/订单的关联。
- 拒绝在刷新、experience=false、旧API再次提交analytics=true及迟到后台事实时继续执行。财务分析在创建/更新旧订单映射**前**锁定并检查proof。广告选择、active_source、来源内容及旧付款快照不随C拒绝被重写。
- 拒绝标记继承该次C偏好的`updated_at/expires_at`。后来广告授权创建新旧proof，仍用原C期限；不能从广告请求日期重新开始24个月。已有有效标记不因旧接口请求延长。新一次明确C拒绝沿偏好原规则更新；到期不等于自动授分析权限。
- 旧有效拒绝，包括仅会话中的旧拒绝，继续阻断C；本批没有提供解除旧拒绝的回开能力。C allow不等于已开启，仍须真实context允许且再start；旧拒绝无法解除时返回off/`LEGACY_DENIED`。
- C-only关闭只确认本站分析。全部可选用途须分别确认C deny及旧v1 `analytics=false/advertising=false`；其中一方失败不能显示全部关闭。两API故障、revision冲突及数据库保存点回滚均有测试。
