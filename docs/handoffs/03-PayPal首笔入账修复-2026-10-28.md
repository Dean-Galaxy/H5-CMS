## 校验与入账变化

1. 官方列表计数是可选字段；存在时仍须类型和数量一致，非空列表不接受total_pages=0，多页及任意大小写NEXT均拒绝。按原订单时间起分30天窗口读取，重叠ID必须内容一致；全部去重交易数=官方执行次数，并逐笔核对Sale、金额、币种、订阅、付款时间及last_payment。双读不稳定则事务不落账，继续占位。
2. 仅一个已完成执行时，已核实原WEEK/1计划、首惠、金额、无债/失败、唯一交易及Sale后，使用官方 `[start_time,next_billing_time)`。须为正区间、不超过168小时，实际paid必须落在区间；不使用当前时间、不加任意容差。
3. 已存首期边界不可重算。之后只能从已保存的官方首个到期点逐周推导，并和新的官方next_billing_time严格一致。无首期观察的多笔历史，只接受原先可严格证明的整周序列；非整周历史留待核对，不倒推猜测首期。Stripe及PayPal续费的Internal ExternalPayment仍要求整168小时，仅PayPal首期允许上述真实短区间。
4. 本人原幂等键显式重查触发 `sync(subscriptionId, allowLifecycleChanges: false)`，只读取平台事实并写正常账本事务，不能调用平台create/cancel/suspend。没有新订单、新订阅、手动加会员。付款、权益和PaymentSettled outbox一次落地，广告消费者失败不阻塞。
5. 审批链接只从当前官方原订阅GET获得，并核验本人原单/计划/固定请求、原有31分钟展示窗口及订阅状态。ACTIVE、未知、读取失败均不返回缓存approve链接。ACTIVE本身仍不等于付款。
6. 默认后台sync仍保留已有到期审批/已取消到期订阅的清理行为，因此00只想核对原付款时应显式使用false；不直接把全局reconcile当只读工具。

## 安全诊断

首单待核错误使用固定阶段码 `PAYPAL_RECONCILE_IDENTITY/TRANSACTIONS/PLAN/SALES/STABLE_READ/CYCLE/LEDGER/HISTORY`，仅写站内原单last_error；对外错误格式保持。

请求失败日志固定消息 `billing.paypal.transport_failure`，仅四项：

| 字段 | 内容 |
|---|---|
| operation | 固定枚举，如oauth、verify_webhook_signature、read_webhook、read_subscription、read_transactions、read_sale等 |
| http_status | 已收到的整数状态；没有响应或业务状态未知时null，不猜测 |
| failure_class | network / api_rejected / invalid_json / invalid_response |
| provider_code | MALFORMED_REQUEST_JSON、INVALID_REQUEST、AUTHENTICATION_FAILURE、PERMISSION_DENIED、RESOURCE_NOT_FOUND、VALIDATION_ERROR、INTERNAL_SERVICE_ERROR、UNPROCESSABLE_ENTITY；其他统一unknown |

不记录URL、带ID路径、查询参数、请求或响应正文、请求头、Authorization、原始异常链、签名、邮箱或姓名。日志失败不改变对外安全异常。原全局request_id上下文可供00关联服务器请求，但不能据时间相近就断言是哪条通知。

## 官方依据及工程判断

2026-10-28核查 [Subscriptions v1列表接口](https://developer.paypal.com/api/subscriptions/v1/subscriptions-transactions/)及[官方OpenAPI schema](https://developer.paypal.com/api/subscriptions/v1/schema.json)：transactions_list的total_items/total_pages未列为必需；cycle_execution的tenure_type/sequence/cycles_completed为必需。[订阅定义](https://developer.paypal.com/api/subscriptions/v1/definitions/subscription/)将next_billing_time定义为下次计费时间；[计划计费周期](https://developer.paypal.com/platforms/subscriptions/customize/billing-cycles/)定义计划频率。

API仍使用PayPal Subscriptions v1、Payments Sale v1、Webhooks v1；本次查阅schema.info.version为1.11，不将它冒称请求Header版本。没有新增事件映射：SALE.COMPLETED仍触发官方Sale+订阅/交易核对，生命周期事件仅作核对线索；REFUNDED/REVERSED按原实现处理。

官方文档并未承诺本项目这笔首期为何少于168小时，也不能据文档自动推导任何短期。上述“唯一首期采用官方两端、后续固定可信锚点”的规则是00接收的保守工程映射，结合本次官方事实，并非PayPal提供了逐笔period字段。
