# direct-test-1 窄组合实测

应用实际起点 **bc4e1a86adcb13abf86b5684892b02f199e9e5be**，业务契约1.0.5/direct-test-1；06仅新增组合测试及证据，不改业务。测试源SHA和逐场景断言数见[实测摘要](evidence/06/direct-test-combination-20261101/summary.json)。本轮 **7场景/337断言通过**；原12项离线预检、R1人工、旧官方支付/退款及全产品套件未重跑。

真实执行：Laravel进程内HTTP客户端经01会话/CSRF及直连中间件、04 `GET /membership`生成可提交draft→首次`POST /membership/checkout`→真实05 AttributionRecorder/CheckoutContextStore写加密上下文。该端口没有替换。显式派发合成可信PaymentSettled后，真实05监听器/收件/去重/门槛/worker和两平台adapter运行；`Http::preventStrayRequests`，仅两平台指定URL由fake拦截。不是实际浏览器、公网TLS或官方支付链路。

| 实际场景 | 本轮结果 |
|---|---|
| Meta、TikTok各一条购买/发送链 | POST前无上下文、redirect后无付款收件/广告发送；显式合成事实才生成收件/发送记录。最小Purchase键、USD实付3美元、稳定event_id、真实GET所固定的无query `/membership`和对应平台匹配字段逐项核对；不含内部ID/邮箱/手机号/交易种类/优惠/LTV。 |
| 两平台重试及重投 | 首次fake503→61秒后fake接受，冻结载荷及HTTP字节相同；重复POST复用原key/context，重复事件仅1收件/1发送记录；已接受再投不重复发。`api_accepted`只是fake返回路径。 |
| 两平台撤回 | 首次fake503后，通过真实tracking consent HTTP保存广告deny；到重试时blocked/CONSENT_REQUIRED_OR_REVOKED，仅首次1次HTTP，没有撤回后发送。 |
| 两平台缺失capture | draft真实存在，但当前请求UA空使真实捕获端口返回null；Billing替身仍收到原合法购买和六字段来源，未造context；合成事实在发送侧blocked/CHECKOUT_CONTEXT_REQUIRED，无HTTP。 |
| staging与production | 同一加载测试应用内实际RuntimeGuard校验staging；刻意analytics=true仍返回analytics denied/unavailable；C/R1/分析、subject/账户关联零新增。production默认开关false/provider null，强开受控位被拒绝。不是生产主机启动证据。 |

替身边界：复用AcquisitionTestCase的合成员工/可推广片单/专用test像素与符合准入形状的来源行；来源从创建即为测试所需eligible形状，没有把实际模拟来源改成真实数据。BillingService与MembershipReader显式Mockery替身，订单只存内存、不写账本；verified观众直接合成，不测试注册/真实邮件。PaymentSettled为代码明确构造的FirstSubscription/300美分/test事件，**不是替身checkout自动发、不是浏览器成功页或官方Webhook证明**。此套断言账务订单/付款/权益/outbox均0，不能据此宣称03账本已再验或付款成功。

初次在GET购买页遇到401/SESSION_REVOKED，为06多请求夹具复用员工Cookie、JSON默认不带Cookie及未保存会话版本造成；首败版本/摘要私密保留。参照现会话工具修正观众Cookie、withCredentials和会话save后，首个Meta局部通过，再运行最终7场景。没有移除认证/CSRF/Guard或修改业务修复；未建立产品缺陷。
