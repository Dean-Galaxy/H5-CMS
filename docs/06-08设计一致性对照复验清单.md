## 必做页面与配对场景

先从原型 manifest/实现说明确认其标注的页面和交互名称，再为每个实际存在且本轮候选实现的场景建立一对截图。下面为覆盖框架，不假定未在原稿出现的设计细节：

| 场景 | 固定页面状态/数据 | 操作序列与取证点 |
|---|---|---|
| 内容主入口与列表 | 同角色、同分栏、同搜索/筛选、同数量代表数据、同滚动位置 | 从后台入口进入对应模块；配对入口导航、页标题/说明、主次操作、列表列/卡片、空白与间距层级 |
| 批量上传起点 | 原稿 `approved-fragment.html` 的批量上传入口、同一合成剧/集及待处理素材 | 按原稿打开批量上传弹窗；配对入口、弹窗标题/尺寸、映射区、步骤指示和操作区。原稿明确要求选择文件后进入核对；常驻分集表单不视为流程等价 |
| 上传核对与提交 | 同批次文件数、文件名及集数映射 | 依原稿执行“选择文件→核对集数→上传与处理”；核对每集映射/摘要后，再明确开始上传。配对记录返回、取消、开始控件、处理中状态与真实服务端回执 |
| 校验错误 | 使用安全的合成无效输入触发一个原稿覆盖的校验错误 | 在错误出现后截图；记录错误定位、文案层级、字段关联、焦点/滚动变化；确认原输入是否保留。不得伪造服务端成功 |
| 取消 | 弹窗/流程中途，填写一项未提交的合成输入 | 点击取消/关闭并按原稿操作；记录是否有未保存确认、确认选择、关闭结果及后台数据未变证据 |
| 返回/上一步 | 已完成至少一步但尚未提交 | 使用原稿规定的返回/上一步；确认已填内容保留或按稿清除，并配对记录焦点、滚动位置、步骤标题和入口回退状态 |
| 编辑方式及列表 | 原稿指定列表、详情或编辑入口与相同数据 | 从列表打开编辑，再保存/取消返回；检查原稿要求的行内编辑、详情页或对话框方式是否一致，禁止仅以数据可保存判为一致 |

若获批稿未定义某一状态，记录“原稿未规定”，由00/08确认判定基准；不要由06补造设计要求。若候选没有对应功能入口，按原稿定义记录首个偏差点和复现，而非跳过场景。

## 每个场景的操作与判断记录

按原型交互逐项执行并录像或连续截图。视口、缩放和页面状态必须一致；00-23指出用户既有截图视口不同，不能据此作逐像素误差结论。应以同条件配对图和源码确认的结构/交互目标判断，不把不同视口截图直接作像素比较：

1. 打开指定角色的后台起始页，记录 URL 路径（不含敏感 query）、视口、初始状态和代表数据。
2. 点击设计指定的入口；保存操作前截图和入口元素定位/可访问名称。
3. 批量上传逐步执行入口 → 弹窗 → 选择文件 → 核对集数映射 → 明确开始上传与处理；每个状态分别拍原型、候选配对图，并记录映射值、按钮动作和状态变化。
4. 在独立新流程中触发错误、失败、取消和返回/上一步；逐一记录首个状态分歧、错误是否保留输入、取消后数据是否未变、返回后数据是否按设计保留。成功或定时结果不得伪造；所有示例成功定时器不作为实现依据。
5. 对提交流程，以浏览器网络回执和只读数据库/页面重读验证实际结果；截图只作为视觉证据。未经批准不做会影响07的写入。
6. 记录每步“相符 / 不相符 / 未验 / 原稿未规定”。任何可见结构、交互方式或状态反馈与原稿不同，附候选 SHA、步骤、首个分歧、预期/实际、影响和配对截图路径；不得以可操作、HTTP 200、无溢出或测试通过抵销设计差异。

## 证据目录结构

每个固定候选建立独立目录，例如 `docs/evidence/06/admin-ui-design/<candidate-sha>/`，含：

- `README.md`：设计归档 SHA/摘要、候选 SHA/契约、环境、视口和浏览器、角色/数据说明、测试者、时间、最终逐项结论。
- `comparison.csv` 或 Markdown 表：原稿文件/页面/状态、操作步骤、原型截图、应用截图、结果、差异、缺陷编号。
- `prototype/` 与 `application/`：按相同场景名存放原始截图，文件名含候选短SHA和视口；不得只保留拼接图或裁切图。
- `sequence/`：必要时保存去敏短录屏/操作事件清单，不能含凭据或用户数据。
- 提交/错误及数据状态的脱敏回执；没有后端证据的场景标记“仅视觉观察”。

本清单交付阶段不生成上述候选结果目录，因为新候选、执行窗口和成对实测尚未提供。
