## 验收原则和准备状态

- 每次验收先记固定候选 SHA、工作树状态、契约版本、依赖审计和迁移结果；运行中的服务及证据必须绑定该 SHA。候选变化后，旧结果只作为历史证据。
- UI 原型的 32 项检查只证明样稿交互。不得把它记作应用、数据库、权限、媒体或浏览器验收。
- 00 已冻结内部 admin-ui-v1 接入边界。06 等待 00 给出共享组件与 01/02/03/05 同一组合提交；在此之前不运行该改版的应用检查。
- 复验使用 06 独立工作区、独立测试数据库和合成记录。不得复制其他工作区的账号、媒体、价格、数据库或环境文件。
- 浏览器可视化操作、Livewire/HTTP 服务端结果、数据库事实分别记录；截图只证明当时画面，不替代持久化和权限检查。
- 发现业务问题时记录候选 SHA、角色、对象、前置数据、操作步骤、预期/实际、首个失败环节、影响和证据路径，交 00 回派原模块。06 不改业务模块或公共根配置。

## 执行和证据记录

收到固定候选后，先保存 `git rev-parse HEAD`、`git status --short`、契约读取值、依赖锁摘要和空测试库迁移输出。随后运行仓库统一契约检查，以及 Identity、Content、Billing、Acquisition 对应 Feature 测试和必要 Integration/Security 测试；由 00 的实际启动说明在独立端口启动 Laravel/队列/定时任务，再用浏览器逐条操作 UI01–UI10。不得从旧测试摘要推定新版本通过。

每条结果只记为“通过 / 失败 / 未执行 / 外部条件未具备”。失败项附固定 SHA、合成数据说明、复现步骤、首个失败环节和不含敏感数据的证据。测试库、日志和媒体在本任务独立路径，完成后记录停止方式和清理结果。若候选变更，按受影响范围重跑；若涉及公共组件或跨模块合同，由 00 决定重跑矩阵。
