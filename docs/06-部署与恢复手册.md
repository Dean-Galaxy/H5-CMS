## 备份、独立恢复和不覆盖新付款的回退

本次真实完成：47 张表的逻辑行摘要一致、42 个媒体文件 SHA-256 一致；第二个 PostgreSQL 实例恢复并实际停启；订单/付款/权益/部分退款/续费状态及加密 MFA 可读；执行两次过期发布没有新增公开集数。恢复目录和备份只有本机私有副本。云主机重启、异地取回、备份加密传输和正式站恢复均未执行。

测试站运行后安排每日逻辑备份（暂定目标 RPO 24h；更低目标需要 WAL/持续归档设计和实际演练），媒体发布变更时同步备份。数据库 dump 与媒体清单必须对应同一维护窗口：暂停上传/发布写入，等待在途媒体处理完成；保留付款通知的持久接收或由支付平台重投/官方对账补齐，不能静默丢通知。APP_KEY 与必要密钥单独加密保管，不能只有数据库没有解密钥匙。

以下命令由授权运维在私有目录执行，连接凭据使用 0600 的 PGSERVICEFILE/PGPASSFILE，不出现在命令历史。service 名仅示例，事先核实指向独立测试站；实际异地目标和加密公钥必须由持有人提供：

```sh
umask 077
# 先记录版本、迁移状态与 UTC 时间，并为本次备份创建全新目录。
pg_dump 'service=h5_staging_backup' -Fc --no-owner --no-acl -f database.dump
# 确认媒体处理/发布已暂停且不存在在途写入后：
tar -C /srv/h5/shared -cf media.tar media
sha256sum database.dump media.tar > SHA256SUMS
# 使用预先核对的 age 公钥加密；私钥不在备份主机和 Git。
age -R /etc/h5/backup-recipients.txt -o database.dump.age database.dump
age -R /etc/h5/backup-recipients.txt -o media.tar.age media.tar
```

随后上传到专用私有桶的唯一时间戳前缀，校验远端大小/摘要与权限；不得使用会删除远端旧备份的同步参数。密文离机成功前保留本地副本；保留策略由用户确认，不在本次删除任何备份。

独立恢复必须用另一台/另一个实例的新库名，应用网络出口默认关闭，不运行网页、队列或 scheduler；恢复时先使所有邮件/广告/支付外发不可用，不能给客户重发或重试退款。不得直接把生产配置改为 testing 运行外部网站。

```sh
# 由恢复管理员在全新隔离 PostgreSQL 实例执行，目标库已存在时停止。
PGSERVICE=h5_restore_admin createdb --owner=h5_restore h5_restore_unique
```
