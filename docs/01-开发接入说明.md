# 01 开发接入与工作区

本机已验证 Apple Silicon、macOS 26.2。PHP 在 `/opt/homebrew/opt/php@8.4/bin/php`，PostgreSQL 在 `/opt/homebrew/opt/postgresql@17/bin`；脚本使用绝对路径，不要求改全局 PATH。Composer 与契约校验依赖在每个工作区自己的 `.runtime`。PHP/PG 是共享只读程序，运行数据不共享。

## 同一基线创建工作区

00 接收 `docs/handoffs/01.md` 后，记录已验收 main 提交。下面是 **后续执行示例，本次没有启动 02–06**：

```sh
cd /Volumes/KESU/H5
git rev-parse main
# 将下面的 BASE 替换为 00 已确认的完整提交哈希。
git worktree add /Volumes/KESU/H5-worktrees/02-content -b work/02-content BASE
cd /Volumes/KESU/H5-worktrees/02-content
python3 scripts/bootstrap.py
python3 scripts/dev.py start
```

03/04/05 同样从相同的 BASE 建自己的分支/目录；01 接收后的修复也走 `work/01-identity`。不要复制整个主目录、`.env`、`.runtime`、数据库或 `原版/`。共同文档、AGENTS、OpenAPI 和锁文件已由 Git 跟踪，会随工作区进入。

Bootstrap 校验官方 Composer 文件摘要，执行 `composer install`，生成随机密钥，再发现应用包/发布 Filament 资源，按锁文件建立契约校验环境。重复执行保留已有配置和数据。依赖下载可能需要联网；这里不请求系统 sudo 密码，也不购买服务。若本机 PHP/PG 缺失，脚本使用已存在的 Homebrew 从官方源安装指定大版本；非本机环境交 01/06 核对。

首次分配端口可指定：

```sh
python3 scripts/dev.py setup --port 8202 --db-port 5602
```

应在 bootstrap 前执行此命令。未指定时按路径生成候选端口并找空闲端口；当前主工作区固定首次优选 8101/5541。已有配置不会被上述参数覆盖，端口被占用会拒绝抢占。确需改已有端口，先停止，再由开发任务同时修改 `.runtime/workspace.json`、`.env` 的 APP_URL/DB_PORT 和该实例 postgresql.conf 的 port，并重新启动；旧邮件链接不会自动迁移。

## 隔离边界

| 项目 | 方案 |
|---|---|
| 路径身份 | `.runtime/workspace.json` 绑定本工作区绝对路径，发现复制配置拒绝使用 |
| PostgreSQL | 每工作区独立 `.runtime/postgres` 实例，仅监听 127.0.0.1；SCRAM 随机密码，应用账号无超级用户权限 |
| 开发/测试数据库 | `h5_<路径摘要>` / `h5_<路径摘要>_test`；测试启动必须匹配 H5_TEST_DATABASE 并以 `_test` 结尾 |
| 会话与缓存 | 各自数据库表；`H5_WORKSPACE` 缓存前缀及观众/后台不同 cookie 名 |
| 队列与定时 | 各自 jobs 表、DB_QUEUE 名称、工作进程；不共用可清空的队列 |
| 文件 | `.runtime/media`、`.runtime/mail`、`.runtime/logs` 各自独立，默认无真实素材 |
| APP_KEY | 每工作区随机生成；后台验证器密钥加密依赖此值，不可随意更换 |

`start` 幂等启动数据库、迁移、网站、queue:work、schedule:work。`stop` 按本工作区登记的 PID 和命令路径检查后停止进程，再停止自己的数据库；无清库命令。网站使用 Laravel 官方开发路由器和 PHP 内置服务器，仅本机访问，非生产服务器。健康检查强制绕过系统代理，确认实际 HTTP 和数据库连通。

开发库的数据库凭据见本工作区 `.env`；可用于本机数据库客户端。不要粘贴到聊天、文档或截图。测试必须通过 `python3 scripts/dev.py test`。本阶段未使用 Node/Vite；页面静态资源直接提供，Filament 资源由已锁定包发布。04 如需构建系统由 00 收敛依赖。

## 模块接入约定

1. 自己的服务提供者放 `app/Modules/<模块>/...ServiceProvider.php`，由 00 接入 `config/h5.php` 的 provider/ready；共同 `AppServiceProvider` 先绑定未就绪提供方，再注册真实模块，真实模块覆盖对应接口。不要只把 ready 改成 true。
2. 维护 `routes/modules/<模块>.php`。当前文件中的 503 是占位，业务提供方接入时由归属任务替换。`/health` 的模块状态是接入状态，不替代外部媒体、支付或广告可用性探测。
3. 后台在 `app/Modules/<模块>/Filament/{Resources,Pages,Widgets}` 自动发现；统一 staff guard、SessionProtection 和 StaffPanelMfa 生效。每项真实读取/写入再调用 `IdentityContext::requireStaff(Permission, ResourceScope)`；ResourceScope 只能从服务端业务记录形成，不能信任浏览器提交的 ownerId/核实状态。
4. 网站使用 `<x-layouts.site>` 默认内容 slot、可选 title、`@push('head')` 与 `@push('scripts')`。04 接管布局、样式与完整翻译；01 维护身份表单及交互。切换语言支持 en/zh_CN，当前统一错误说明未作为完整全站翻译交付。
5. 业务提供方只依赖 `app/Contracts` 和 `app/Data`；`examples/` 不会在普通运行时导入。未实现或外部状态不明确必须显式失败。AttributionService 关闭返回 null，不冒充已验证来源。
6. Cashier 依赖已锁定，但自动发现被关闭，没有 Billable、Stripe 配置、支付表或自动路由。03 接入前申请共同配置变更、核对 API 版本，保持唯一 `/webhooks/stripe` 入口。
