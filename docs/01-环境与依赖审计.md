共锁定 164 个直接/传递 PHP 包（含开发依赖）。`composer validate --strict` 及 `check-platform-reqs` 通过；显式要求 pdo_pgsql、mbstring、intl、fileinfo，避免换工作区后只满足框架最低扩展却连不上 PostgreSQL。版本记录在 `scripts/runtime-lock.json`，全部精确 PHP 包版本在 `h5-platform/composer.lock`；后续依赖更新由 00 串行发布。

PHP 8.4 当前仍受维护，安全支持至 2028-12-31；Laravel 13 支持 PHP 8.3–8.5，安全支持至 2028-03-17。选择 8.4.26 同时满足已安装依赖的 PHP 要求。参见 [PHP 支持周期](https://www.php.net/supported-versions.php)、[Laravel 13 支持政策](https://laravel.com/framework/docs/13.x/releases)、[Filament 5 安装要求](https://filamentphp.com/docs/5.x/introduction/installation)。

PostgreSQL 17 的支持至 2029-11-08，当前使用已更新的 17.11；不选测试版 19。参见 [PostgreSQL 版本政策](https://www.postgresql.org/support/versioning/)。系统程序允许同一大版本后续安全补丁，更新后仍需重新记录审计和回归，不能仅修改文本版本。

## 已知安全修补核对

- Composer 对锁定依赖在线审计：`advisories=[]`、`abandoned=[]`，没有已报告命中。原始结果保存在 `docs/evidence/01/composer-audit.json`。这是当日通告结果，不意味着不存在未知问题。
- Filament 官方通告 GHSA-52xp-w8hr-xv3c 涉及启用恢复码时的应用二次验证绕过。已锁定 5.9.0，超过官方 5.7.0 修补版本；实际覆盖空恢复码拒绝、密码不能直接登录、动态码及恢复码重复消费。参见 [Filament 安全通告](https://github.com/filamentphp/filament/security/advisories/GHSA-52xp-w8hr-xv3c)。
- PHP 8.4.26 是当前安全发布，来自官方 Homebrew 配方；参见 [PHP 官方发布](https://www.php.net/index.php)。
- PostgreSQL 官方 17 安全表列出的最新修补在 17.11，包括 pg_dump/psql 客户端及服务器问题。本机已用该版本的服务器和客户端；参见 [PostgreSQL 17 安全公告](https://www.postgresql.org/support/security/17/)。没有使用旧备份、旧库或外部不可信 SQL。

## 安装与运行边界

已完成 Homebrew 官方源安装 PHP 8.4 和 PostgreSQL 17；Composer 取自 getcomposer.org；PHP 包取自官方包的锁定源。没有启动系统级 PostgreSQL 服务。本项目使用 `.runtime/postgres`，不使用安装器产生的 `/opt/homebrew/var/postgresql@17` 空实例；未申请公网端口或采购外部服务。

本阶段页面直接使用静态资源和 Filament 自带资源，不依赖 npm，因此无前端 npm 供应链审计结果。契约校验工具另用 Python venv，并在 requirements-contracts.lock 锁定。系统 Python 3.9 的 LibreSSL 会触发 urllib3 版本提示；这里的 OpenAPI 校验不联网，HTTP 冒烟仅访问 127.0.0.1，不用它发送外部业务请求。正式 CI 的 Python/SSL 环境由 06 单独配置。

本机 `.env`、APP_KEY、PostgreSQL 密码、预览邮件、数据库及审计数据全部排除 Git。网页日志不持久记录完整签名 URL；异常日志只保存异常类型和关联号，审计字段采用白名单。生产配置会拒绝本地预览、模拟、HTTP APP_URL 或开启 debug，但 HTTPS、代理、邮件和生产进程仍需 06 实际部署验收。
