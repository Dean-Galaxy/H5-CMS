# 05 游客分析与隐私低打扰方案

2026-10-30｜**待 00 审议的产品建议，不是已确认规则或实施放行。** 本轮仅文档，不改变当前 `analytics-v1`、D05、应用、配置、数据库、广告外发或人工窗口。主文供产品决策；源码和官方依据在附录。

## 一、建议先取消自动弹窗，把计数、关联分析和广告分开

**推荐 A：游客先浏览、试看；入口不自动打开选择框。经核准的美国范围内，可默认做不建立访客关联的基础运营计数；关联的本站分析与广告测量分别自愿开启。资格或技术边界未核清时，退回 B：只运行必要功能，不采未获同意的可选行为，仍不自动弹窗。** 页首/播放器附近提供简短告知和可随时打开的设置，页脚永久保留隐私入口；观看仍受原地区、版权和会员规则约束，不能为统计放宽。不能先采集完整轨迹，再等注册时补同意。若主要目标是未注册游客的逐访客顺序漏斗，A只是活动总量的折中；应明确选择C先做适用核定、核定后再开发，而不是把A当成目标已满足。

游客是否注册，与能否合法分析是两件事。游客也可以主动选择关联分析；注册页不能成为唯一选择入口。原首次自动弹窗是现有保守实现，**不是“美国所有访问都依法必须先点同意”**。美国规则需按主体、州、用途、年龄与第三方实际使用判断；本站分析也不自动等于跨站定向广告。[CA 收集时告知与用途限制](https://cppa.ca.gov/pdf/20260101_ccpa_statute.pdf)、[CO 官方同意适用说明](https://coag.gov/resources/colorado-privacy-act/)

### 1. 四层用途与默认边界

| 层次 | 做什么、为什么 | 推荐默认及数据边界 | 不应对用户说什么 |
|---|---|---|---|
| 必要业务/服务 | 登录安全、试看许可、用户要求的续播、下单、付款/权益、必要安全防护 | 按具体服务处理会话、账户/进度、可信账务；必要留存单独定，不转作营销漏斗。不因拒绝可选用途阻塞使用或付款 | “必要功能包含所有运营分析” |
| 基础运营计数 | 知道哪些页面类型有访问、发生几次真实播放/门槛展示 | **条件性默认**：先核主体/美国适用规则、告知、网络与日志、退出机制。只保存“UTC 日 × 页面类型 × 事件类型 × 环境/政策版本”的计数；不建立访客/会话/账户关联。属于可选运营用途，不直接称技术必要 | “无 Cookie 就匿名”“覆盖全部游客”“可算逐人流失” |
| 关联的本站分析 | 看合法样本跨页、登录/付款衔接和顺序漏斗 | 推荐仍主动选择后开始，游客可选；建立伪名主体/会话，合法登录后限本次链路关联账户。拒绝不采，不跨设备猜测，不补之前行为 | “只是本站就不算个人数据”“注册即同意分析” |
| Meta/TikTok 广告测量 | 用获准来源与可信付款做广告回传 | 独立可选，初始关闭；还需年龄/地区/退出信号/平台及视频隐私核定。当前外发继续关闭；不把全部本站事件发送平台 | “勾选就必定能发”“HTTP 接受等于平台归因成功” |

基础计数启用前，设置页必须让人看懂其默认状态和关闭方式，**不能用同一个未勾选的“本站分析”暗示所有计数都关闭，后台却继续计数**。建议设置列出“基础运营计数”“关联本站分析”“广告测量”三个实际状态；关联分析和广告默认不勾。注册页只增加独立可选用途入口，基础计数状态可跳转设置查看。最终控件由 08 与 00 统一，不能直接用当前两个布尔值强行表达三种许可。

### 2. 能看什么，损失什么

| 能力 | 无访客关联的基础计数 | 合法可关联样本（推荐仍 opt-in） |
|---|---|---|
| 游客未注册也有信息 | 有：页面可见、真实播放、门槛展示的**次数**；不会知道这些是不是同一人 | 有：从授权之后记录；不要求先注册 |
| PV / 实际播放 | 页面可见每次页面呈现一次；播放需时间实际前进，预加载/请求不算。刷新是新一次；没有 UV | 可分别报访问次数、主体/会话去重人数、有效观看，单位分开 |
| 到门槛 / 付款 | 门槛展示次数；账务另由 03 报去重付款笔数/金额，两者不强联 | 同一入口群、按时间顺序及固定观察窗算漏斗；未经过全部步骤的合法付款另列 |
| 退出 / 停留 | 首版不做退出追踪。不能从总次数差推断谁退出、退出在哪；pagehide 也可能只是切后台 | 只能报观察到的停留；“观察窗内无后续”是近似流失，仍在观察中单列。关机/断网/拦截导致缺失 |
| 去重 / 重试 | 仅页面内存防重复触发；无跨页/跨日/跨设备去重。建议尽力发送一次、不持久补发，承认丢失/重复风险 | 在授权后用事件 ID 幂等和有界重试；清数据、换设备、撤回仍造成断链 |
| 比较与覆盖 | 只能比较同口径事件量；播放次数/PV 可称“次数比”，**不能称同人转化率** | 明示“可关联且符合资格的样本”。识别会话数不能除以 PV 称人数覆盖率；拿不到全体合法人数分母就不报人数覆盖率 |

两类报表并排，不拼成“全量匿名漏斗”。A仅按实际保存的UTC日、页面类型、事件类型、环境/测试属性及政策版本做同口径比较，不提供地区或渠道筛选。渠道比较须另行受控设计，不能把个人广告来源接回A。合法关联样本也只按其实际可用维度比较，缺失维度不能假定一致；样本扩大或换采集方法后不能宣称转化提升。默认计数没有渠道/剧集维度，不能据此评估单广告或单集掉人。真实付款收入来自 03；本站统计不是平台归因或 ROAS。默认计数也会受拦截、网络、预加载识别误差影响，不能承诺 100% 覆盖。

### 3. 交互、历史状态与实施决策

| 场景 | 推荐行为（未实施） |
|---|---|
| 首次进入 | 不自动弹框；在可选计数开始前提供可见、可理解的告知及设置。不能仅藏页脚；必要服务照常。基础计数资格不明就关闭 |
| 游客随时选择 | 播放器下方文字入口 + 页脚“隐私设置 / Your Privacy Choices”；打开才展示选择；关闭/播放/沉默都不是同意 |
| 注册 | 账户条款接受与隐私告知单独呈现，不伪称所有必要处理都依赖同意；关联分析、广告各自可选且不预勾。账户成功但设置失败时，保留账户、提示用途未开启，不要求重复注册 |
| 拒绝全部 / 撤回 | 停全部可选用途，**包括基础运营计数**；清可选缓冲/当前关联，待发及重试重新判断。必要服务和既有可信账务保持；历史删除/权利请求另走明确机制，不承诺撤回等于已删除所有数据 |
| 部分拒绝 | 不将广告拒绝误作分析许可，反之亦然。既有明确 analytics denied/withdrawn 至少阻止基础计数及关联分析，除非用户以后在充分告知下主动变更；旧拒绝不可静默升为 granted |
| GPC / 其他有效退出信号 | 服务端优先落实广告出售/共享/定向用途退出，不能靠前端 POST 又勾回；不重复劝开。GPC 不自动替代本站分析同意，也不自动禁止所有必要处理。独立分析明确拒绝仍优先 |
| 地区未知 | 只必要；基础计数、关联分析和广告均不因普通勾选绕过资格判断。不主动收 GPS/精确地址；当前 country=US 不足以核定州/居住资格。解释“当前未开启”，不假报已保存授权/成功采集 |
| 已有同意/历史订单 | 继续按原目的、版本与有效状态判断；新目的重新告知/选择，不扩大旧同意。政策允许的未来第一方处理与主动 consent 证据分开存，不能自动 POST analytics=true |
| 广告来源与付款 | 保留已确认 D05：**同意后 7 天内最后有效推广点击、建单固定、普通访问不覆盖、撤回停外发**。未获准点击 ID 不延迟保存；注册延迟同意不倒填旧来源/旧行为；无来源不阻塞付款 |

### 4. 三个选项及需要拍板的事

| 选项 | 产品收益 / 代价 | 建议 |
|---|---|---|
| **A 条件性基础计数 + 自选关联分析/广告** | 低打扰，可观察未注册阶段的活动量；得不到所有人的路径，需要独立数据通道、告知和退出语义 | **推荐产品方向**；核定前采用 B，不先放全美国 |
| **B 无自动弹窗 + 未同意仅必要功能** | 最小改动、承接现有 opt-in 边界；多数未选择游客不会进入行为报表，样本偏差需接受 | A 未核准时的默认实施候选 |
| **C 先核定美国适用条件，再开发第一方会话分析默认开、易退出；广告另选** | 面向未注册游客的逐访客顺序漏斗目标；可覆盖更多路径，但仍非全量。会处理可关联个人数据，需核主体、地区/年龄、用途、告知、合同和权利执行 | **可选择先做适用核定，核定后再开发**；核定前不启用，不以A总量替代该目标 |

00/本人只需集中决定：①选A并以B兜底、先只做B，或**选C先做适用核定，核定后再开发**；②若选A，是否接受只到页面类型/次数、不能回答逐访客或单集掉人；若目标是游客顺序漏斗，应优先核定C；③是否接受设置中单列基础计数，已有拒绝继续尊重；④美国首发受众年龄与实际州覆盖如何界定，以及由谁补齐下述事实核定。台湾、新加坡、日本本轮不纳入，未知地区不先放开。**本建议不授权实施或法律合规结论。**

### 停止采集与保存失败，不能只靠一句提示

A建议采用**浏览器无访客标识上报计数，服务器直接增量汇总**，不把所有HTTP请求/访问日志自动转成分析计数。浏览器先判断有效政策资格与必要的拒绝偏好；拒绝/撤回先暂停本浏览器可选采集、取消尚未发送的计数，再提交并回读服务端状态。多标签传播暂停；下一次访问优先读取拒绝偏好，读不到资格/设置则退B。偏好存储只用于执行选择，不能兼作分析ID。不能从必要安全日志补丢失计数。

本机停止与服务端生效是两步：先用仅执行选择的必要偏好记录拒绝，并暂停本浏览器受控上报；再提交必要的偏好变更，收到服务端成功回读后，才确认对应服务器设置已生效。若本机偏好也无法保存，当前页面仍暂停，后续读取失败退B，但不承诺跨刷新已永久记住。必要偏好不携带行为队列、不充当访客关联ID；无关安全日志独立按必要目的处理，不能因拒绝而谎称全部日志停止，也不能用它们补产品分析。

设置保存失败时，只能说“本浏览器可控制的可选采集已暂停，服务器设置尚未确认”，保留草稿供重试；**不能宣称历史待发广告/其他设备已停止**。广告发送进程仍须实际读取服务端撤回/GPC等门禁；确认失败不伪报撤回完成。已经发送且接收的计数无法逐人撤销，因为无逐人索引；保留这一限制告知，停止未来可选处理。若后续选用服务器HTTP自动计数，须另解拒绝偏好实时传达、缓存及失败行为，未解前不能套用A承诺。
